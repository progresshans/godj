## 상태와 범위

이 ADR은 **Accepted**입니다. Acceptance는 scalar v2 bytes를 보존하는 explicit relation IR v3와 exact
ForeignKey DSL, additive relation companion/project bridge, immutable atomic `orm.BindProject`, existing
migration tuple/state의 relation pre-I/O rejection, mixed product comparator와 REL-001 metadata actual에만
적용합니다. Query/loader/cache/write/delete/DDL/relation migration codec, non-AutoField target,
OneToOne/ManyToMany와 PostgreSQL/MySQL/Windows support는 결정하거나 구현한 것으로 보지 않습니다.

## 맥락

ADR-0023은 relation-capable 제품이 stable symbolic model identity, source-owned declaration, atomic all-app
binder, generated app-to-app import edge 0의 project bridge와 shared relation AST를 사용해야 한다고
Accepted했습니다. 그러나 current Schema IR v2는 scalar `auto`/`char`/`boolean`만 표현하고 existing migration
definition tuple `(1,1,1,2)` 및 generator `godj-codegen-m2-v3`와 직접 결속되어 있습니다. Exact vNext
version/tag/encoding, DSL constructor, schema companion/binder/bridge API와 scalar key representation은 의도적으로
남겨 두었습니다.

첫 product packet은 REL-001 metadata만 구현해야 합니다. Query/join/cache/write/delete/DDL까지 한 번에
확장하면 single-table Query AST/compiler, result scan ABI, transaction/delete collector와 migration codec를
동시에 바꾸게 되어 contract와 failure ownership을 검증할 수 없습니다. 반대로 relation metadata를 v2의
reserved value 또는 runtime side map으로 숨기면 Schema IR single-source invariant와 old consumer fail-closed를
깨뜨립니다.

따라서 GDJ-0024는 AutoField-target ForeignKey declaration과 generated scalar storage, atomic project-bound
forward/reverse metadata만 고정합니다. Exact canonical encoder tag/API/error/generator/bridge decision은 아래
표와 compile/wire/error contract로 Proposed 상태에서 먼저 동결했고 implementation/audit/hosted evidence 뒤
이 bounded shape만 Accepted했습니다.

## 결정 기준

- Scalar IR v2 canonical JSON/hash/generated bytes와 migration tuple의 byte compatibility
- Relation meaning의 lossless canonical single-source representation
- Required/nullable AutoField FK scalar storage의 compile usability
- Mutual cross-app relation에서 generated app-to-app import cycle 0
- All-or-nothing project binding과 deterministic structured errors
- Caller mutation/alias, concurrent read와 global registry contamination 방지
- Actual generated code/bridge와 runtime metadata가 같은 relation edge를 사용
- Relation migration accidental acceptance의 pre-I/O fail-closed
- REL-001 actual observation이 expected constants/fixture replay 없이 검증 가능
- REL-002..012 미구현이 success로 숨지 않는 product comparison
- 기존/새 hosted gates의 failure isolation과 exact inventory

## 고려한 선택지

### Current IR v2 field에 optional relation side data 추가

V2 normalizer가 optional value를 받아들이면 canonical v2 bytes/hash가 relation meaning에 따라 달라지고
migration definition tuple `(1,1,1,2)`가 relation을 우연히 운반할 수도 있습니다. Version rejection과
single-source versioning을 보장하지 못하므로 채택하지 않습니다. 이번 packet은 새 public raw JSON decoder를
추가하거나 unknown/duplicate JSON key 정책을 고정하지 않습니다.

### Scalar FK field와 별도 schema-level relation list

Physical column과 relation target을 분리해 parallel identity/order/duplicate diagnostics가 생깁니다. Storage와
semantic relation이 서로 다른 field를 가리키는 invalid state를 별도로 막아야 합니다. ADR-0023 feasibility의
explicit field-union arm보다 ownership이 복잡하므로 채택하지 않습니다.

### Target generated app를 source generated app가 직접 import

Typed target을 쉽게 표현하지만 `authors ↔ blog` mutual relation에서 Go import cycle을 만듭니다. Build tag,
interface extraction 또는 one-direction exception은 user package graph를 schema 방향에 종속시키므로 채택하지
않습니다.

### Runtime global registry와 incremental binding

`init()` 순서와 test/import order가 외부 결과를 바꾸고 missing target/reverse collision 실패 전에 일부 edge가
노출될 수 있습니다. Concurrent project/test isolation과 deterministic validation을 어렵게 하므로 채택하지
않습니다.

### Explicit IR vNext, schema companions, project bridge와 immutable binder

Old v2를 byte-preserve하고 relation-bearing input을 explicit version으로 구분합니다. App packages는 source
declaration/scalar storage와 additive schema companion만 생성하고 project bridge가 all-app schema snapshots를
binder에 전달하므로 cycle을 피합니다. Global validation 뒤 한 immutable set을 publish하면 partial binding을
원천 차단할 수 있습니다.
이번 packet에 채택합니다.

### Versioned field-union relation arm

`ir.FormatVersion=2` remains the scalar/default version and new `ir.RelationFormatVersion=3` identifies a
relation-capable schema. `ir.Normalize`, `CanonicalJSON` and `Hash` normalize zero to v2 and accept exact 2 or 3.
Existing IR v2 normalization, canonical serialization/hash, main generated output and `godj-codegen-m2-v3` remain
byte-identical. A v2 field with a relation arm is rejected rather than dropping relation meaning. V3 may contain the
same scalar field tags plus the explicit relation arm.

```go
const FieldForeignKey FieldKind = "foreign_key"

type ModelIdentity struct {
	AppLabel  string `json:"app_label"`
	ModelName string `json:"model_name"`
}

type Field struct {
	// existing fields retain their tags
	Relation *ForeignKeyRelation `json:"relation,omitempty"`
}

type ForeignKeyRelation struct {
	Target      ModelIdentity       `json:"target"`
	Cardinality RelationCardinality `json:"cardinality"`
	Reverse     ReverseRelation     `json:"reverse"`
	OnDelete    DeletePolicy        `json:"on_delete"`
}

type RelationCardinality string
type DeletePolicy string

const (
	RelationManyToOne RelationCardinality = "many_to_one"
	RelationOneToMany RelationCardinality = "one_to_many"
	DeleteProtect     DeletePolicy        = "protect"
	DeleteSetNull     DeletePolicy        = "set_null"
)

type ReverseRelation struct {
	Name     string `json:"name,omitempty"`
	Disabled bool   `json:"disabled,omitempty"`
}
```

The relation field arm owns one source field identity and physical FK column plus:

- canonical target `(app_label, model_name)`
- key kind `AutoField`
- cardinality `many_to_one`
- nullability
- explicit reverse name or explicit reverse-disabled state
- delete policy metadata needed by the declarations (`PROTECT`, `SET_NULL`)

The arm cannot carry primary-key/max-length/default state. `ReverseRelation` is exactly explicit `name` xor
`disabled:true`; cardinality is exact `many_to_one`; policy is exact `protect|set_null`. Invalid symbolic identity,
reverse/policy/cardinality and `set_null` on a non-null field fail in v3 normalization. Each normalized model has
exactly one AutoField primary key; project binding resolves only target model existence and reverse namespace. Canonical
JSON/order/hash are independent from Go type/import alias, input map order and post-snapshot caller mutation. This ADR freezes the
canonical encoder tags and Marshal+Normalize round-trip only; it adds no public raw JSON decoder or unknown/duplicate
raw-key contract.

Required and nullable FK values generate `int64` and `*int64` scalar storage. This represents target keys only;
it does not expose target objects, loaders, caches or typed relation query selectors.

The exact DSL types are `type ModelTarget = ir.ModelIdentity`, `type ReverseRelation = ir.ReverseRelation` and
`type DeletePolicy = ir.DeletePolicy`. Constructors are exact
`func Target(appLabel, modelName string) ModelTarget`, `func RelatedName(name string) ReverseRelation`, and
`func NoReverse() ReverseRelation`. The surface also includes `schema.ModelTarget{AppLabel, ModelName}` and
`schema.Protect`/`schema.SetNull`.

```go
func ForeignKey(
	name, goName string,
	target ModelTarget,
	reverse ReverseRelation,
	onDelete DeletePolicy,
	options ...FieldOption,
) Field
```

`schema.Build` emits v3 if any ForeignKey exists and otherwise preserves scalar-only v2 behavior. `ForeignKey`
sets physical `Column` to exact `name + "_id"` before options; `schema.Column(...)` explicitly overrides it. Direct v3
`ir.Schema` input converges on the same representation: `ir.Normalize` defaults an empty foreign-key `Column` to exact
`field.Name + "_id"` and preserves an explicit Column. Scalar v2 empty Column keeps the existing `field.Name` default and
byte behavior.
Public `schema.Field` gains exported `Relation *ir.ForeignKeyRelation`; `Build` deep-copies that nested value before
normalization so declarations cannot alias emitted IR.
`func (f ir.Field) Clone() ir.Field` deep-copies both `Default` and nested `Relation`; `Model.Clone` uses it.
Normalization, binding, generated companions, `ExecutePlan` retained plans, `NewStateReconstructor`/lifecycle
definition snapshots and `migrations/definition` clones cannot alias a caller's relation pointer. Direct
`Executor.Apply`/`Unapply` operation alias/race semantics remain unchanged and out of scope.
Callers must not mutate any input concurrently while Normalize/Build/Generate/Bind/clone is running; deep-copy does not
make an unsynchronized input writer race-free. After a successful snapshot/return, later caller mutation cannot affect
retained values, and `ProjectBinding` concurrent reads/accessors are race-safe. Mutation/race tests therefore cover
post-snapshot mutation plus concurrent reads, not an arbitrary writer racing the input call.

### Generated packages and project bridge

REL-001 deliberately mixes a scalar v2 target-only `authors` schema and relation-source v3 `blog` schema. Existing
v2 main `codegen.Generate` bytes are literally unchanged. V3 `Generate` branches only after Normalize and emits plain
model structs with `int64`/`*int64` FK scalar fields. Its exact exported surface is
`GoDjGeneratorVersion="godj-codegen-rel-v1"`, `GoDjSchemaSHA256`, and those plain model structs/fields only; no relation
descriptor, method or accessor is emitted in main output. Relation IR/schema accessors exist only in the companion.
The branch uses exported codegen constant `RelationGeneratorVersion="godj-codegen-rel-v1"`; generated output
contains no symbol with that Go identifier and contains no `db`, `query`, `Manager`,
`WriteDescriptor`, relation query selector/loader or relation create/update API.

Every participating v2 or v3 app gets an additive companion generated by:

```go
func GenerateRelationMetadata(packageName string, input ir.Schema) ([]byte, error)
```

The companion records exact `GoDjRelationMetadataGeneratorVersion="godj-codegen-rel-v1"` and
`GoDjRelationSchemaSHA256`, and exports
`GoDjRelationSchema() ir.Schema` returning a fresh deep copy. It does not alter the main v2 output; a v3 main and
companion must compile in the same package without symbol collision. Project bridge input is exact
`type BridgePackage struct { Alias string; ImportPath string }` and
`GenerateProjectBridge(packageName string, packages []BridgePackage) ([]byte,error)`. The deterministic bridge has
version `godj-codegen-rel-project-v1` through exact `GoDjProjectBindingGeneratorVersion`, uniformly imports app
companion packages plus `orm`, and exports
`Bind() (orm.ProjectBinding,error)` which calls
`orm.BindProject(app.GoDjRelationSchema()...)`. The generator binary never imports generated targets; app packages do
not import each other; the bridge cannot parse raw DSL/JSON or duplicate relation values.

Same input is byte-deterministic/gofmt. `Generate`, `GenerateRelationMetadata` and `GenerateProjectBridge` return
bytes only. Completion tests generate, format, externally compile and bind the complete multi-app
main/companion/bridge candidate bytes, and prove candidate-validation failure never mutates pre-existing committed
output sentinels. This is validation-path no-write behavior, not a product publication or rollback API.
Existing single-file `WriteFile` semantics/bytes remain unchanged. Caller publication, an atomic project-set writer,
CLI generate/check and replacement/rollback/crash consistency belong to a later bounded packet. External mixed
v2/v3, mutual and self-relation projects must compile with exact zero generated app-to-app import edges.

Dedicated `conformance/relationproduct/**` owns checked-in generated `authors`/`blog` main+companion files, project bridge and
an observer that imports the bridge and returns actual `Bind()` metadata. Candidate bytes regenerated from declaration
schemas must be byte-equal without rewriting tracked outputs. The GoDj relation adapter calls only this observer and
never reads oracle/static fixtures or expected REL-001 constants. Separate external mutual/self projects own compile
and exact app-to-app import-edge-zero proof.

### Atomic immutable project binding

`orm.BindProject(schemas ...ir.Schema) (ProjectBinding,error)` accepts exactly one schema per app in a mixed set of
v2 target schemas and v3 relation-source schemas. It snapshots all input schemas, rejects duplicate app-label inputs,
validates normalized source columns, resolves all target model identities, derives forward/reverse projections,
validates reverse namespaces and only then constructs one
immutable result. Any failure returns no accessible partial result. `ForwardRelations` is sorted by exact
`(Source.AppLabel, Source.ModelName, Field)` and `ReverseRelations` by exact
`(Owner.AppLabel, Owner.ModelName, Name)`; lookup is input-order independent. After the duplicate-app precheck,
first-failure selection uses that same canonical source-relation order.

The binder has no global registry or `init()` hook. Input/output mutable containers do not alias internal state, and
successful values support concurrent reads. Forward and reverse metadata are two projections of the same bound edge,
not manually duplicated declarations.

Public immutable values have the following exact inspectable fields; identity reuses `ir.ModelIdentity`.

```go
type RelationMetadata struct {
	Source      ir.ModelIdentity
	Field       string
	Column      string
	Target      ir.ModelIdentity
	Nullable    bool
	Cardinality ir.RelationCardinality
	Reverse     ir.ReverseRelation
	OnDelete    ir.DeletePolicy
}

type ReverseRelationMetadata struct {
	Owner       ir.ModelIdentity
	Name        string
	Target      ir.ModelIdentity
	SourceField string
	Cardinality ir.RelationCardinality
}

type RelationBindingErrorCode string

type RelationBindingError struct {
	Code        RelationBindingErrorCode
	AppLabel    string
	ModelName   string
	FieldName   string
	Target      ir.ModelIdentity
	ReverseName string
}

func (e *RelationBindingError) Error() string

const (
	RelationBindingDuplicateApp          RelationBindingErrorCode = "duplicate_app"
	RelationBindingUnresolvedTarget      RelationBindingErrorCode = "unresolved_target"
	RelationBindingReverseNameCollision RelationBindingErrorCode = "reverse_name_collision"
)
```

`RelationMetadata.Field` and `ReverseRelationMetadata.SourceField` are normalized source `ir.Field.Name` values.
Reverse `Owner` is the target model that owns the reverse namespace and reverse `Target` is the relation source model.
Forward cardinality is `RelationManyToOne`; derived reverse cardinality is `RelationOneToMany`.
`ForwardRelations()` and `ReverseRelations()` return fresh slices, and
`Relation(source ir.ModelIdentity, field string)` performs the exact forward lookup without exposing maps. Zero-input
BindProject is a valid empty binding. `RelationBindingError` carries the reachable exact typed constants above.
`duplicate_app` fills only `AppLabel`; `unresolved_target` fills source `AppLabel`/`ModelName`/`FieldName` and `Target`;
`reverse_name_collision` fills those source fields plus `Target`/`ReverseName`; unused fields are zero. BindProject
returns `*RelationBindingError` directly or wraps it only with `%w`, guaranteeing `errors.As`. Target AutoField-only, per-schema duplicate
model/field/relation and invalid identity/reverse/policy/set-null-nullability errors remain `*ir.ValidationError` from
Normalize rather than dead binder codes.

### Migration compatibility boundary

`definition.DefinitionFormatVersion=1`, `LoaderABIVersion=1`, `OperationCodecVersion=1`,
`SchemaIRVersion=2` and `migrations.StateFormatVersion=1` remain literal and unchanged. `NewProjectState` and state
validation reject format 3 before execution I/O. CreateModel/AddField keep their v2 wrapper and reject relation arms.
`NewStateReconstructor` also preflights each cloned built-in `CreateModel` model field and `AddField.Field`: if a cloned
field has `Kind == ir.FieldForeignKey` or `Relation != nil`, it returns exact structured `*migrations.Error` with
`CategoryState`, `CodeInvalidState`, `DirectionForward`, migration identity and operation index/kind. The cause states
the relation-v2 incompatibility rather than reusing the unsupported operation-type diagnostic; neither a definition
snapshot nor reconstructor is published. `Executor.Migrate` calls this constructor before backend capability checks,
revision-fenced session open and recorder reads, so this lifecycle rejection performs exact zero backend/recorder I/O.
Definition tuple schema_ir 3 retains existing `schema_ir_incompatible`; a tuple-2 document that
hides a relation shape fails with exact existing `definition.CodeInvalidIR` / `invalid_definition_ir` and its
semantic field path. `ir.Field.Clone`, `Model.Clone`, `ExecutePlan` retained-plan clone,
`NewStateReconstructor`/lifecycle definition snapshot and `migrations/definition` clone deep-copy nested relation state
even on rejection, so post-snapshot caller mutation cannot change those retained values. This does not add a universal
Apply/Unapply operation snapshot. Relation migration codec/DDL is a later contract packet.

### REL-001 product and partial comparison

GDJ-0024 implements only REL-001 metadata from actual generated app companions/bridge/binder output. REL-002..012 remain
`oracle_locked` and produce ordered payload-free `not_implemented` observations. The full original 12-contract
manifest/oracle ordering remains the comparison boundary.
REL-001 presentation includes forward `name`, `column`, target, nullable, `many_to_one=true`, reverse and `on_delete`,
plus reverse `name`, source field, target and `one_to_many=true`. It maps actual IR `protect`/`set_null` tokens to
oracle enum spelling `PROTECT`/`SET_NULL` without reading or replaying expected fixtures.

Product comparison requires:

- `passing`/`deviation` → observed
- `oracle_locked` → not_implemented without payload
- `red`/`draft`/unknown, missing, duplicate or reordered entries → command failure
- an exact required-observed ID set matching all passing/deviation IDs; REL-001 is the only such relation ID
- unknown passing scenario → failure before actual-output publication

The exact internal seams are
`protocol.CompareProduct(profile, manifest, expected, actual, requiredObserved []string) ([]Difference,error)` and
`godjrunner.RequiredObservedContractIDs(manifest) ([]string,error)`. Required-observed IDs are derived from the actual
GoDj handler registry, never from manifest status or expected values. `Generate` executes registered handlers,
produces payload-free not-implemented only for unregistered `oracle_locked`, and errors for unregistered
`passing|deviation` or red/draft/unknown status. The command retains strict `Compare` for locked-expected
self-validation and existing all-observed manifests; mixed actual must pass `CompareProduct` before any
`-actual-output` write.
Validated REL mixed success prints exact
`GoDj product observations match 1 required contract; 11 remain not implemented\n`, with both counts derived from the
validated actual/manifest. Existing all-observed success text is unchanged, and tests reject any mixed success that
claims all 12 contracts were implemented or matched.

The strict reference `Compare` remains available and still reports not-implemented as mismatch. Relation oracle/static
fixture/SHA bytes are immutable; only reviewed REL-001 manifest status changes. Product completion becomes exact
`12 adapter sets/127 contracts = 111 passing + 5 deviation + 11 oracle_locked`, with relation actual coverage `1/12`;
the baseline remains `11 adapter sets/115 contracts = 110 passing + 5 deviation`.
Django runner/scenario/oracle stay immutable; only the Python manifest-status assertion changes to exact one `passing`
followed by eleven `oracle_locked`, without changing the Python test count or scenario digest.

## 결과

- Relation meaning gains an explicit versioned canonical source without silently changing v2 consumers.
- Cross-app AutoField FK scalar storage and forward/reverse metadata can compile without app import cycles.
- Atomic binder validation and immutable publication add a project-wide generation/runtime step and structured errors.
- Public/ABI responsibility is limited to the exact decision table; query/load/write/delete/migration APIs remain open.
- Product conformance can represent honest partial progress without filtering away 11 unimplemented contracts.
- Four additional hosted jobs increase CI cost but isolate actual relation product failures from test-only feasibility.

- Typed/dynamic relation query selector and shared relation-path AST public API
