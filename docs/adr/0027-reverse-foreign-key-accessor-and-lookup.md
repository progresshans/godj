## 맥락

ProjectBinding은 forward relation과 derived reverse namespace를 이미 immutable snapshot으로 보관합니다.
ADR-0025는 forward target predicate와 INNER JOIN을, ADR-0026은 sealed object descriptor와 instance-owned cache를
구현했습니다. 하지만 runtime `query.RelationDirection`은 forward만 알고, dynamic relation parser는 reverse를
명시적으로 거부하며 SQLite compiler는 root가 FK source인 path만 허용합니다.

REL-005는 두 외부 동작을 동시에 요구합니다.

- freshly loaded Author에서 `posts` accessor를 평가해 Post IDs `[10,11]`, SELECT 1, JOIN 0
- `posts__title=Alpha` lookup을 평가해 Author IDs `[1]`, SELECT 1, INNER JOIN 1

Accessor만 구현하면 shared relation AST와 typed/dynamic convergence가 없고, lookup만 구현하면 future
REL-012가 사용할 owner-instance related-set ownership을 다시 설계해야 합니다. 반면 REL-012까지 묶으면 현재
없는 IN-list AST, two-stage coordinator, grouping과 warm-cache publication을 동시에 고정하므로 범위가 과도합니다.

## 결정 기준

- Existing relation metadata/query/object generators와 checked-in generated bytes를 보존
- Physical FK declaration identity를 잃지 않는 immutable reverse path
- Query-only reverse binding과 owner-PK-dependent accessor capability를 분리
- Caller callback/Manager, original descriptor retention과 hot reflection 금지
- Typed/dynamic predicates가 같은 path/plan으로 수렴하고 atomic error precedence를 유지
- Source FK exact QuerySet와 existing cache/singleflight/cancellation/retry를 재사용
- Project package만 cross-app concrete types를 연결하고 app-to-app import edge 0 유지
- Deterministic reverse DB name to Go selector transform와 namespace fail-close
- SQLite direction-specific root/join validation과 pre-I/O invalid path rejection
- REL-005만 passing으로 전환하고 나머지 seven relation contracts를 payload-free NI로 유지

## 고려한 선택지

### Reverse query와 accessor를 하나의 handle로 결합

Accessor는 owner instance의 present primary key가 필요하지만 predicate construction은 그렇지 않습니다. 하나로
결합하면 object capability가 없는 read-only descriptor의 typed lookup은 실패하는데 dynamic lookup은 성공할 수
있습니다. Query/object capability를 분리합니다.

### ReverseRelationMetadata에 column/nullability를 추가

현재 reverse entry `(Owner, Name, Target, SourceField)`를 canonical forward entry `(Source, Field)`와 결합하면
source column, nullable, target과 delete/cardinality를 복원할 수 있습니다. Public binding metadata ABI 변경은
불필요하므로 채택하지 않습니다.

### WriteDescriptor 또는 caller PK callback 사용

`WriteDescriptor`는 read-only reverse lookup에 과도하고 original mutable descriptor retention 위험이 있습니다.
Callback은 bound model/field와 구조적으로 연결되지 않아 false green을 만들 수 있습니다. Existing sealed object
descriptor에 `PrimaryKey`만 더한 좁은 dynamic capability를 사용합니다.

### 기존 project object generator를 확장

기존 generator version과 golden/checked-in bytes를 바꾸고 GDJ-0026 surface를 소급 확장합니다. New project-only
reverse companion으로 분리합니다.

### REL-005와 REL-012를 한 packet으로 구현

REL-012에는 immutable IN-list, two-stage prefetch, grouping, cancellation과 warm related-set attach가 필요합니다.
REL-005의 one-query accessor/lookup과 독립 ownership decision이므로 후속 packet으로 둡니다. 이번 `RelatedSet`
private ownership은 additive future extension을 막지 않지만 speculative warm API/state는 만들지 않습니다.

## 결정

### Declaration-centric reverse RelationPath

Exact additive query surface:

```go
const RelationReverse RelationDirection = "reverse"

func NewReverseRelationPath(
	source ir.ModelIdentity,
	sourceTable, sourceField, sourceColumn string,
	target ir.ModelIdentity,
	targetTable, targetPKColumn, reverseName string,
	nullable bool,
	terminal FieldRef,
) (RelationPath, error)

func (h RelationHop) ReverseName() string
```

Hop state remains declaration-centric:

| Property | `Author.posts <- Post.author` |
|---|---|
| Source / table | `blog.post` / `blog_post` |
| Field / source column | `author` / `author_id` |
| Target / table / PK | `authors.author` / `authors_author` / `id` |
| Direction / traversal cardinality | `reverse` / `one_to_many` |
| Nullable | original `Post.author` value |
| ReverseName | `posts` |

Existing `Field()` returns `author`; existing source/target/column accessors and forward constructors remain unchanged.
`ReverseName` is private immutable state included in `Equal` and clone. Reverse constructor accepts only canonical
nonblank identities/identifiers, exactly one reverse one-to-many hop and related-field terminal. It sets terminal scope
`related_field`. It does not expose SQL aliases or descriptor pointers.

### Query-only reverse binding

```go
type ReverseRelation[Owner, Source any] struct { /* private */ }

func BindReverse[Owner, Source any](
	owner BoundModel[Owner], reverseName string, source BoundModel[Source],
) (ReverseRelation[Owner, Source], error)

func (r ReverseRelation[Owner, Source]) Integer(
	field IntegerField[Source],
) (RelatedIntegerField[Owner], error)

func (r ReverseRelation[Owner, Source]) String(
	field StringField[Source],
) (RelatedStringField[Owner], error)
```

Resolution first finds exact reverse `(owner identity, reverseName)`, then reconstructs the physical declaration from
forward `(reverse.Target, reverse.SourceField)`. It validates declaration target equals owner, reverse name/cardinality,
source field/column/model, owner AutoField and same immutable snapshot. It requires neither owner PK presence nor
`RelationObjectDescriptor` capability. Terminal fields reuse existing non-null Auto/Char support and existing related
field predicate types, now parameterized by Owner.

### Object/accessor capability

```go
type PrimaryKeyObjectDescriptor[M any] interface {
	RelationObjectDescriptor[M]
	PrimaryKey(M) (query.Value, bool)
}

type ReverseObject[Owner, Source any] struct { /* private */ }
type RelatedSet[M any] struct { /* private QuerySet and _self */ }

func BindReverseObject[Owner, Source any](
	owner BoundModel[Owner], reverseName string, source BoundModel[Source],
) (ReverseObject[Owner, Source], error)

func (r ReverseObject[Owner, Source]) From(
	backend db.Queryer, owner Owner,
) (*RelatedSet[Source], error)

func (s *RelatedSet[M]) OrderBy(orderings ...Ordering[M]) (*RelatedSet[M], error)
func (s *RelatedSet[M]) All(context.Context) ([]M, error)
func (s *RelatedSet[M]) Fresh() (*RelatedSet[M], error)
```

`PrimaryKeyObjectDescriptor` is asserted only from the already sealed `BoundModel.objectDescriptor` dynamic snapshot.
No new BoundModel field is added and the original descriptor is never retained. Existing generated v2 AuthorDescriptor
supplies presence-aware `PrimaryKey`; numeric zero is not used as a presence test. A v3 owner without this capability
may use `BindReverse` but `BindReverseObject` fails `CategoryQuery/CodeInvalidPlan` before I/O.

Both owner and source object descriptors must be generated immutable named non-pointer zero-size snapshots.
`BindReverseObject` internally derives the source Manager, a private scalar exact predicate from the canonical
ForeignKey `FieldRef`, and source AutoField ordering. It does not pass a ForeignKey through the public AutoField-only
`IntegerField` constructor. `From`
deep-clones owner through the sealed descriptor, rejects nil/typed-nil backend as
`CategoryBackend/CodeInvalidPlan` and missing/wrong-kind PK before I/O,
then creates source FK exact QuerySet with source PK ascending order. Missing present PK preserves the established
`CategoryQuery/CodeMissingPrimaryKey` taxonomy with the PK field; invalid kind/null is `CodeInvalidPlan`.

`RelatedSet` delegates evaluation to this private QuerySet. `All` therefore inherits deep clones, successful result
cache, singleflight, waiter cancellation, owner-cancel retry and backend/scan/rows/close failure retry from ADR-0012.
`OrderBy` and `Fresh` produce new valid pointers/evaluation state and perform no I/O. `_self` rejects nil, zero,
composite and dereference-copy receivers with `invalid_plan`. No public Filter/IN/prefetch/warm injection is added.

### Dynamic reverse parser

Additive exact API:

```go
func ParseDynamicReverseRelations[M any](
	owner BoundModel[M], policy LookupPolicy, inputs []LookupInput,
) ([]Predicate[M], error)
```

The dedicated parser avoids changing the byte/semantic contract of existing generated forward delegates. It accepts
only exact two-segment implicit-exact named reverse lookup such as `posts__title`. Error precedence is:

1. exactly two non-empty segments and no lookup suffix/multi-hop
2. reverse namespace
3. target terminal and supported non-null Auto/Char shape
4. policy with fresh canonical terminal and `LookupExact`
5. value parse
6. all-or-nothing publication

Typed and dynamic paths call the same reverse resolver and constructor; their predicates and Plans must be Equal.

### SQLite compilation

The compiler supports exact one-hop `related_field` conditions in either direction.

- forward root: `Plan.Table == hop.SourceTable`; join target table;
  `t0.SourceColumn = tN.TargetPrimaryKeyColumn`
- reverse root: `Plan.Table == hop.TargetTable`; join source table;
  `t0.TargetPrimaryKeyColumn = tN.SourceColumn`

Reverse terminal fields are qualified with the joined alias. Required and nullable physical FK declarations both use
INNER JOIN for a target-value reverse predicate. Join keys include direction as well as physical source/field/target;
forward and reverse uses of a self relation cannot collide. Same reverse edge predicates reuse one join. Reverse name,
direction/cardinality, root table, canonical declaration strings, target PK column, terminal `FieldRef` and lookup/value
are validated before backend I/O. The compiler has no project model snapshot and does not claim to revalidate semantic
model membership; `BindReverse` owns source/target/table/field/PK equality before it constructs the path. Existing
scalar, forward related-field and nullable source-key SQL/args/errors remain exact.

### Generated project companion

Exact additive codegen surface:

```go
const ProjectRelationReverseGeneratorVersion = "godj-codegen-rel-reverse-project-v1"

type RelationReversePackage struct {
	Alias      string
	ImportPath string
	Schema     ir.Schema
}

func GenerateProjectRelationReverse(
	packageName string, packages []RelationReversePackage,
) ([]byte, error)
```

Input schemas are cloned, normalized and canonically sorted. The generator resolves each named reverse declaration and
AutoField target before rendering. It emits a separate file and never rewrites existing per-app/project generators.

The REL-005 fixture's exact publication union contains nine generated files: authors main, metadata and object;
blog main, metadata, query and object; project binding bridge and the new reverse companion. The scalar-v2 authors main
already provides the owner descriptor/PK and does not require an authors query companion. This pure generator does not
read a filesystem or prove prerequisites: it owns clone/normalize, namespace validation, render and gofmt. A missing or
ABI-incompatible prerequisite is a caller publication/union-compile failure; external compile tests prove that failure
does not replace last-known-good files. A same-surface provenance-version value remains a publication-workflow check;
the generator does not emit non-idiomatic per-byte type assertions for a string constant.

Generated query aggregate:

- `ReverseRelations`, `BindReverseRelations()`
- every named edge, including `AuthorsAuthor.Posts.Title` and `AuthorsAuthor.ReviewedPosts.Title`
- owner `ParseDynamic` delegating to `ParseDynamicReverseRelations`

Generated object aggregate:

- `ReverseObjects`, `BindReverseObjects()`
- PK-capable From-only owner factory `AuthorsAuthor.From(backend, author)`; no duplicate typed/dynamic query fields
- opaque `*AuthorsAuthorReverseObject` owning cloned model and one private `*RelatedSet[blog.Post]` per named edge
- error-bearing `Model()`, `Posts()`, `ReviewedPosts()` and `Fresh()`, all self-sentinel checked

The exact fixture-facing declarations are additive:

```go
type AuthorsAuthorReviewedPostsReverseRelation struct {

	policy orm.LookupPolicy, inputs []orm.LookupInput,

type ReverseRelations struct {
	AuthorsAuthor AuthorsAuthorReverseRelations
}

func BindReverseRelations() (ReverseRelations, error)

type AuthorsAuthorReverseObjectFactory struct {
	// private bound object handles and descriptor
}

func (f AuthorsAuthorReverseObjectFactory) From(
	backend db.Queryer, model authors.Author,

	AuthorsAuthor AuthorsAuthorReverseObjectFactory

func (o *AuthorsAuthorReverseObject) Model() (authors.Author, error)
func (o *AuthorsAuthorReverseObject) Posts() (*orm.RelatedSet[blog.Post], error)
func (o *AuthorsAuthorReverseObject) ReviewedPosts() (*orm.RelatedSet[blog.Post], error)
func (o *AuthorsAuthorReverseObject) Fresh() (*AuthorsAuthorReverseObject, error)
```

`BindReverseObjects` creates all private object handles from one local project snapshot; it does not compose a
separately created `BindReverseRelations` result or expose duplicate query fields. Factory `From` clones the owner
through the generated descriptor, uses that clone for both runtime bindings, and publishes the wrapper only after all
fields and `_self` are valid. Repeated calls to one accessor return the same valid related-set pointer; `Posts` and
`ReviewedPosts` have independent caches. `Fresh()` reuses the captured backend/model/factory but constructs an
independent wrapper and both related-set evaluation states.

Query and object aggregate binding are independent and atomic. Query generation/binding includes valid reverse owners
without object PK capability; object aggregate emits only owners whose generated descriptor contract is known to
satisfy `PrimaryKeyObjectDescriptor`. Direct runtime binding remains the structured enforcement boundary.

Reverse selector transform accepts ASCII lower-snake with non-empty non-digit-leading segments, capitalizes each
segment and concatenates it: `posts -> Posts`, `reviewed_posts -> ReviewedPosts`. Leading/trailing/repeated underscore,
punctuation/non-ASCII, a raw whole name or any segment equal to a Go keyword or `init`, and empty values fail before
bytes. Validation rejects transformed collisions and all fixed aggregate/version/import/model symbols, query-owner
`ParseDynamic`, wrapper `Model`/edge accessors/`Fresh`, object-factory `From`, private names and immutable prerequisite
declarations. Locals and receivers use underscore-prefixed alias-impossible identifiers. Failure returns nil bytes;
input permutation yields exact bytes.
