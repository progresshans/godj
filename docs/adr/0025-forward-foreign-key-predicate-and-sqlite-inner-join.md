## 상태와 범위

이 ADR은 **Proposed**입니다. GDJ-0025 implementation과 independent API/import/AST/compiler audits가 아래
exact surface를 검증하고, actual REL-004 및 exact hosted CI가 통과한 뒤에만 이 bounded decision을
Accepted로 바꿉니다.

결정 범위는 required AutoField-target one-hop forward relation의 typed/dynamic `Exact` predicate,
immutable shared Query AST와 SQLite reusable `INNER JOIN`입니다. Object loader/cache, nullable relation access/
`isnull`, reverse/multi-hop/eager/write/delete/DDL/migration과 non-SQLite backend는 결정하지 않습니다.

## 맥락

ADR-0023은 symbolic project binding과 typed/dynamic shared relation AST를 선택했고, ADR-0024는 relation IR
v3, plain generated model main, additive schema companion/project bridge와 immutable metadata binding을
Accepted했습니다. 현재 product는 relation source를 `int64`/`*int64` scalar key로 생성하지만 v3 main에
descriptor, manager, query selector 또는 cache를 넣지 않습니다. Query Plan과 SQLite compiler도 single-table
scalar field만 표현합니다.

REL-004는 이 간극을 최소 수직 단면으로 통과합니다. Required `Post.author`의 target `Author.name`/`id`
predicate가 하나의 canonical edge를 공유하고 actual SQLite에서 one SELECT/one INNER JOIN으로 `[10,11]`을
반환해야 합니다. REL-003/006을 함께 묶으면 model instance loader/cache와 nullable relation semantics를 먼저
결정해야 하므로 이번 packet에서는 제외합니다.

## 결정 기준

- existing v2/v3 generated main, relation metadata companion와 project `Bind()` byte/API compatibility
- source app가 target app를 import하지 않는 cross-app compile graph
- generated descriptor/manager가 v3 plain model ABI를 바꾸지 않는 additive surface
- project-bound typed selector와 dynamic lookup의 exact same immutable AST
- caller mutation alias와 concurrent read로 plan/binding이 변하지 않는 ownership
- one/two target predicates가 canonical edge 하나를 공유하는 join deduplication
- no-relation plan의 exact existing SQLite SQL/args/error preservation
- invalid relation input의 compiler/backend pre-I/O fail-closed
- actual SQLite result/query/join metrics와 oracle-blind conformance adapter
- REL-004만 passing으로 전환하고 나머지 relation work를 명시적으로 미구현 유지

## 고려한 선택지

### v3 main에 descriptor, manager와 cache state를 직접 추가

Main model type 하나에 query와 future object cache를 함께 넣기 쉽지만 GDJ-0024의 exact plain struct output을
바꾸고 REL-003 cache ownership을 REL-004가 선결합니다. 기존 generated byte/ABI를 보존하지 못하므로
채택하지 않습니다.

### Source app가 target generated package를 직접 import

Concrete target fields를 source package에서 표현하기 쉽지만 mutual relation에서 Go import cycle이 생깁니다.
ADR-0023의 project bridge ownership을 깨므로 채택하지 않습니다.

### Dynamic string path를 SQLite compiler에서 직접 해석

Typed selector와 dynamic lookup이 서로 다른 의미 경로를 갖고 compiler가 runtime metadata/binding 책임까지
떠안습니다. Construction-time structured error와 AST equality를 증명할 수 없으므로 채택하지 않습니다.

### SQL compiler가 terminal path마다 JOIN 생성

`author__name`과 `author__id`가 같은 edge임에도 두 JOIN을 만들 수 있습니다. Django의 relation traversal과
REL-004 join reuse를 만족하지 못하므로 채택하지 않습니다.

### Additive query companions, project-owned typed wiring and canonical edge AST

Existing generated artifacts를 보존하고 project bridge만 concrete apps를 import합니다. Runtime binding이
source/target/field를 검증한 뒤 typed/dynamic 모두 one immutable path constructor를 사용하고 compiler는
edge identity로 JOIN을 deduplicate합니다. 이 option을 채택 후보로 둡니다.

## Proposed 결정

### Exact generator surface

```go
package codegen

const RelationQueryGeneratorVersion = "godj-codegen-rel-query-v1"
const ProjectRelationQueryGeneratorVersion = "godj-codegen-rel-query-project-v1"

func GenerateRelationQuery(packageName string, input ir.Schema) ([]byte, error)

type RelationQueryPackage struct {
	Alias      string
	ImportPath string
	Schema     ir.Schema
}

func GenerateProjectRelationQuery(packageName string, packages []RelationQueryPackage) ([]byte, error)
```

`GenerateRelationQuery` accepts exact normalized relation IR v3 and emits only a query companion. Existing
`Generate`, `GenerateRelationMetadata`, `GenerateProjectBridge`와 their generated bytes/API remain unchanged.
The companion exports:

- `GoDjRelationQueryGeneratorVersion`
- `GoDjRelationQuerySchemaSHA256`
- `<Model>Descriptor`
- `<Model>FieldSet` and `<Model>Fields` for non-relation scalar fields only
- `<Model>Objects`

It imports `db`, `orm`, `schema/ir` and `database/sql` only when nullable scalar storage (`Char` or FK) needs `Null*`
scanning. It never imports a target app. Descriptor metadata comes from a fresh `GoDjRelationSchema()` value, scan
covers every stored field, and clone deep-copies nullable pointers. No WriteDescriptor/save/create/update/delete/cache
symbol is generated.

Before rendering, it constructs one exact package namespace containing existing `GoDjGeneratorVersion`,
`GoDjSchemaSHA256`, every model `GoName`, `GoDjRelationMetadataGeneratorVersion`, `GoDjRelationSchemaSHA256`,
`GoDjRelationSchema`, the two new query provenance symbols and every derived `<Model>Descriptor`, `<Model>FieldSet`,
`<Model>Fields`, `<Model>Objects`. Any duplicate identifier is a generation error before bytes are returned.

`GenerateProjectRelationQuery` immediately clones and normalizes every `RelationQueryPackage.Schema`. It canonicalizes
and validates app label, alias and compiler-safe import path. Alias must be an ASCII lower-camel Go identifier matching
`[a-z][A-Za-z0-9]*`; Go keywords, `init`, predeclared identifiers used by the generated file (`error`, `nil`) and
reserved import aliases `orm`/`ir` are rejected. The exported prefix uppercases exactly the first ASCII byte and
preserves the remainder, so `blog` becomes `Blog`. Duplicate aliases or exported prefixes are rejected.

Before rendering, the project generator validates three exact namespaces: file imports contain unique `orm`, `ir` and
app aliases; package declarations contain existing `GoDjProjectBindingGeneratorVersion`/`Bind`, new
`GoDjProjectRelationQueryGeneratorVersion`/`Relations`/`BindRelations`, and every
`<Prefix><Model>Relations`/`<Prefix><Model><Relation>Relation` type; the `Relations` aggregate contains unique
`<Prefix><Model>` fields. Within each `<Prefix><Model>Relations` type, relation fields are unique and `ParseDynamic` is
reserved by the exact method. Any collision is rejected before bytes are returned. Generated runtime code calls existing
same-package `Bind()`. It imports `github.com/progresshans/godj/schema/ir` as `ir` and emits only normalized symbolic
`ir.ModelIdentity{AppLabel: ..., ModelName: ...}` values needed by `BindModel`; it never replays fields, tables or a raw
schema literal.

`RelationQueryPackage.Schema` may be scalar IR v2 or relation IR v3. A v2 target uses its unchanged main-file
descriptor; a v3 model uses the additive query companion descriptor. The generated `Relations` aggregate contains only
source models that have at least one supported required forward relation. Target-only models are still bound for type
and snapshot validation but do not gain an empty aggregate entry.

`GenerateProjectRelationQuery` derives each generated relation selector name from normalized FK scalar storage
`Field.GoName`: it must end with the exact terminal `ID`, and removing that suffix must leave a non-empty exported Go
identifier. Thus `AuthorID` becomes `Author`. Missing/empty suffix results, `ParseDynamic`, or duplicate selector names
in one source model are project-generation errors. `Field.Name` remains the symbolic binder key and is not inferred from
this Go spelling. `GenerateRelationQuery` does not create relation selector names and therefore does not apply this
project-surface rule.

The exact fixture-level exported shape is:

```go
const GoDjProjectRelationQueryGeneratorVersion = "godj-codegen-rel-query-project-v1"

type BlogPostAuthorRelation struct {
	ID   orm.RelatedIntegerField[blog.Post]
	Name orm.RelatedStringField[blog.Post]
}

type BlogPostRelations struct {
	Author BlogPostAuthorRelation
	model  orm.BoundModel[blog.Post]
}

func (r BlogPostRelations) ParseDynamic(
	policy orm.LookupPolicy,
	inputs []orm.LookupInput,
) ([]orm.Predicate[blog.Post], error)

type Relations struct {
	BlogPost BlogPostRelations
}

func BindRelations() (Relations, error)
```

Every fallible bind happens inside `BindRelations`. It returns the zero result on failure and never uses package init,
global registry, reflection discovery or panic. Nullable forward relations are not emitted in this packet.

### ProjectBinding model snapshot and bound types

`ProjectBinding` stores normalized models, forward and reverse relations in one private immutable snapshot. Copies may
share that immutable snapshot; accessors return fresh values. Its zero value behaves as an empty unbound snapshot and
does not panic.

```go
func (b ProjectBinding) Model(identity ir.ModelIdentity) (ir.Model, bool)

type BoundModel[M any] struct { /* private */ }

func BindModel[M any](
	binding ProjectBinding,
	identity ir.ModelIdentity,
	descriptor ModelDescriptor[M],
) (BoundModel[M], error)

type ForwardRelation[S, T any] struct { /* private */ }

func BindForward[S, T any](
	source BoundModel[S],
	field string,
	target BoundModel[T],
) (ForwardRelation[S, T], error)
```

`Model` returns `ir.Model.Clone()`. `BindModel` rejects nil/typed-nil descriptors and requires exact semantic equality
between the snapshot model and descriptor metadata. `BindForward` requires source and target from the same snapshot,
an existing required `many_to_one` relation and exact target identity. Nullable relation, wrong source/target/field and
unbound zero values return structured `*query.Error` before I/O.

### Typed and dynamic relation fields

```go
type RelatedIntegerField[M any] struct { /* private sealed state */ }
type RelatedStringField[M any] struct { /* private sealed state */ }

func (r ForwardRelation[S, T]) Integer(field IntegerField[T]) (RelatedIntegerField[S], error)
func (r ForwardRelation[S, T]) String(field StringField[T]) (RelatedStringField[S], error)
func (f RelatedIntegerField[M]) Exact(value int64) Predicate[M]
func (f RelatedStringField[M]) Exact(value string) Predicate[M]

func ParseDynamicRelations[M any](
	model BoundModel[M],
	policy LookupPolicy,
	inputs []LookupInput,
) ([]Predicate[M], error)
```

The target type parameter is consumed while constructing a related field; the result carries the source type so it can
only be passed to `QuerySet[source].Filter`. A wrong target field fails to compile or bind. The two `Exact` methods are
the only related typed lookups in this decision.

`ParseDynamicRelations` accepts exactly two non-empty segments with implicit exact: `author__name` and `author__id`. It
calls the same private forward-path/related-condition constructor as typed fields. Before relation lookup it rejects a
different segment count, any empty segment (`__name`, `author____name`) or an explicit lookup suffix with
`CategoryField` / `CodeUnsupportedLookup`. Nullable `reviewer`, reverse and multi-hop paths are likewise unsupported.
The existing scalar `ParseDynamic` preserves all scalar-field behavior. When descriptor metadata identifies a
`FieldForeignKey` or carries non-nil relation metadata, however, it returns `CategoryField` /
`CodeUnsupportedLookup` before scalar lowering. A public v3 descriptor therefore cannot make `author__isnull` or
`reviewer__isnull` appear supported through the legacy scalar API; REL-006 remains the sole owner of relation-level
`isnull` semantics.

Stable dynamic errors add:

```go
const CodeUnknownRelation = "unknown_relation"
const CodeUnknownRelatedField = "unknown_related_field"
```

Both use `CategoryField`. Extra segments/lookups use existing `CodeUnsupportedLookup`; policy rejection and invalid
values keep existing codes. `errors.As` exposes `*query.Error`, and `Detail` remains non-contract diagnostic text.

Error ownership and precedence are exact:

| Boundary | Category/code |
|---|---|
| nil/typed-nil descriptor, zero/different snapshot, descriptor-model or target mismatch | `CategoryQuery` / `CodeInvalidPlan` |
| missing source relation | `CategoryField` / `CodeUnknownRelation` |
| missing terminal field on the resolved target | `CategoryField` / `CodeUnknownRelatedField` |
| dynamic path not exactly two non-empty implicit-exact segments; nullable/reverse/multi-hop path | `CategoryField` / `CodeUnsupportedLookup` |
| policy rejection or invalid runtime value | existing `CodeDisallowedLookup` / `CodeInvalidValue` |

Validation order is descriptor/snapshot → dynamic path shape → source relation → target identity/AutoField key →
terminal field/kind → policy/value. The first failure is returned and no plan or partial `Relations` value is published.

### Exact immutable relation AST

`query` imports only normalized symbolic types from `schema/ir`; it does not import ORM, codegen or backend packages.

```go
type RelationDirection string

const RelationForward RelationDirection = "forward"

type RelationHop struct { /* private */ }
type RelationPath struct { /* private */ }

func NewForwardRelationPath(
	source ir.ModelIdentity,
	sourceTable, field, sourceColumn string,
	target ir.ModelIdentity,
	targetTable, targetPKColumn string,
	nullable bool,
	terminal FieldRef,
) (RelationPath, error)

func (p RelationPath) Hops() []RelationHop
func (p RelationPath) Terminal() FieldRef
func (p RelationPath) Equal(other RelationPath) bool
func NewRelatedCondition(path RelationPath, lookup Lookup, value Value) Condition
func (c Condition) RelationPath() (RelationPath, bool)
```

`RelationHop` has exact value accessors `Source`, `SourceTable`, `Field`, `SourceColumn`, `Target`, `TargetTable`,
`TargetPrimaryKeyColumn`, `Direction`, `Cardinality`, `Nullable` and `Equal`. They expose symbolic value copies only.
`RelationPath` has exactly one hop in this decision. The constructor rejects blank identities/tables/fields/columns,
nullable paths and invalid terminal fields. AutoField target validation belongs to `BindForward`, which has the full
normalized target model; the generic query constructor does not infer key kind from a column string.

`NewRelatedCondition` stores a deep path copy and uses `path.Terminal()` as `Condition.Field`. Scalar
`NewCondition` continues to have no path. `Condition.RelationPath`, `Plan.Conditions`, cloning and accessors return fresh
copies. `Condition.Equal` and `Plan.Equal` include the complete path. No public raw slice/map/pointer, SQL alias or Go
type enters the AST.

### SQLite compiler decision

`Compile` chooses the current scalar branch when no condition has a relation path. That branch retains exact existing
SQL strings, arguments and error categories. Relation plans use a separate bounded branch.

The relation branch validates compiler-observable path structure before building SQL. It supports exact one required
forward hop and `Exact` only, and requires the hop's source table to equal the plan root table. Join keys are canonical
`(source app label, source model, source field, target app label, target model)` values. Metadata disagreement under one
key is invalid rather than first-wins. Sorted keys receive deterministic aliases `t1..`; root is `t0`. The compiler
does not own a `ProjectBinding`, so target model/key correctness is established earlier by `BindForward` and is not
independently re-resolved from symbolic path text.

Root SELECT, ordering and scalar condition columns are qualified by `t0`. Related conditions use their edge alias and
terminal target column. Values remain `?` parameters. For REL-004 the semantic fragment is:

```sql
FROM "blog_post" AS "t0"
INNER JOIN "authors_author" AS "t1"
  ON "t0"."author_id" = "t1"."id"
```

Both `author.name` and `author.id` share the same `t1`. Reverse/multi-hop/nullable paths, root/source-table mismatch,
inconsistent metadata for a repeated edge, non-exact related lookup and unselected root scalar fields return stable
query/backend errors before `Backend.Query` increments query count or calls `QueryContext`. Wrong source/target model
bindings fail earlier in `BindModel`/`BindForward`, before a relation path exists.

This decision does not define LEFT OUTER JOIN or nullable `isnull` lowering. REL-006 owns those semantics.

### Product and compatibility decision

`conformance/relationqueryproduct/**` is a new independent generated fixture so every existing
`conformance/relationproduct/**` byte stays unchanged. It contains v2 `Author(ID,Name)`, v3
`Post(ID,Title,AuthorID,ReviewerID)`, both existing relation metadata/project binding files and new query companions/
project query bridge.

The actual adapter provisions SQLite tables manually, enables FK enforcement, and observes two real QuerySet results.
This provisioning is test fixture setup, not relation migration/DDL support. It records construction/evaluation query
windows, join classification and final rows from actual execution. Expected relation oracle/static fixture bytes are
never imported by product code.

Only REL-004 changes `oracle_locked → passing`. REL-001 remains passing and the other ten relation contracts remain
ordered payload-free not implemented. Aggregate becomes exact `112 passing + 5 deviation + 10 oracle_locked`.

## Rejected or deferred surface

- `ForwardRelation.Get`, `RelationCache`, hidden model state, loader/singleflight/cancellation ownership
- nullable forward binding, related `IsNull`, NULL fast path, LEFT join and join trimming
- reverse selector/manager, multi-hop, OR/Q, ordering/aggregation, eager/prefetch hydration
- relation assign/save/write/delete and migration/DDL/history support
- app-to-app direct import, global registry, reflection lookup, init panic
- modifying existing v3 main/metadata/project Bind output or generated batch publisher
- PostgreSQL/MySQL/Windows/multi-DB compatibility claims

## Acceptance conditions

This ADR becomes Accepted only if:

1. Exact public API compiles in an external module and negative cross-model/target inputs fail.
2. Existing generated artifacts and scalar SQLite goldens remain exact.
3. New generated app packages have zero direct app-to-app Imports/Deps and project bridge compiles.
4. Bound snapshots and AST values pass mutation, permutation, concurrent-read and race gates.
5. Typed and dynamic plans are equal and construction performs zero backend I/O.
6. Actual SQLite produces `[10,11]`, one SELECT and one INNER JOIN for one/two target predicates.
7. Invalid unsupported paths fail before backend I/O and no expected oracle constants are replayed.
8. Manifest/status-only transition, ten ordered NI outputs, aggregate and no-rewrite gates are exact.
9. Local normal/race/CGO-disabled/vet/repetition/386 and exact 26 hosted executions pass without skip.
10. Independent API/codegen/SQLite/conformance/security audits report P0..P3=0.

If implementation evidence rejects this shape, ADR-0025 remains Proposed and GDJ-0025 records the bounded alternative
rather than silently changing exported API or marking REL-004 passing.

## Consequences

- GoDj gains its first real relation traversal through the complete product stack without committing to object cache.
- Existing plain v3 model ABI remains stable; query support is additive and removable.
- Project bridge remains the only generated package with concrete cross-app imports.
- Query AST now has a canonical edge/path representation that later relation work can extend explicitly.
- SQLite relation compilation stays bounded and old scalar SQL remains a separate compatibility branch.
- Q-013 remains `Partial`: this packet resolves one-hop required predicate shape, not broader relation behavior.
