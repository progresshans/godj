## 맥락

Existing `ModelDescriptor.Scan`은 root model의 exact column count로 `db.Row.Scan`을 한 번 호출합니다. Join target
columns를 기존 Plan에 덧붙인 뒤 source descriptor와 target descriptor를 차례로 호출하면 각 호출의 destination
arity가 실제 joined row와 일치하지 않습니다. 기존 Scan을 바꾸면 모든 generated descriptor bytes와 accepted
QuerySet behavior가 소급 변경됩니다. 따라서 단순 compiler JOIN 추가는 구현 불가능하거나 false green입니다.

REL-009/010은 같은 projection/scanner/cache machinery의 required/nullable 양면입니다. Required만 먼저 고정하면
outer-join NULL presence를 표현하지 못하는 scanner ABI를 잠글 수 있고, nullable만 구현하면 ordinary INNER
baseline을 검증하지 못합니다. REL-011을 단독 오류 branch로 구현하면 eager product 없이 contract-ID stub만으로
passing이 가능합니다. 세 contract는 동일 resolver/AST/runtime/compiler/generator packet으로 묶습니다.

Django 6.1에서 `select_related()`는 manager/QuerySet 진입점과 model instance/accessor를 바꾸지 않고 같은 relation
cache를 미리 채웁니다. GoDj도 이 의미를 장기 기준으로 삼지만, 이 ADR은 그 canonical application facade 전체가
아니라 joined projection과 existing object cache를 연결하는 bounded engine slice만 결정합니다.

## 결정 기준

- Existing named descriptor, Manager/QuerySet, forward object API와 generated bytes 보존
- Root fields + ordered target fields를 한 번의 `Row.Scan`으로 decode
- Required/nullable operation context가 각각 INNER/LEFT OUTER를 결정
- Typed와 dynamic direct path가 같은 project snapshot resolver와 immutable AST로 수렴
- Reverse multi-valued path는 compiler/DB I/O 전에 exact stable error
- Full rowset/resource/context validation 뒤에만 ready result cache 공개
- Root Filter/OrderBy/Limit/Fresh plan meaning 보존, unrelated terminals 미확장
- Existing `BindObjects` snapshot을 재사용하고 eager 전용 project binder를 만들지 않음
- Bounded eager bridge와 장기 canonical application facade를 구분
- Pure deterministic generators, exact union compile와 last-good preservation

## 고려한 선택지

### Existing `ModelDescriptor.Scan`에 joined columns 전달

Descriptor는 root destination만 제공하므로 joined row arity와 맞지 않습니다. Descriptor interface와 모든
generated base file을 변경하지 않고는 안전하게 구현할 수 없어 거부합니다.

### Bespoke cross-app joined descriptor 하나 생성

Fixture에는 동작하지만 relation pair마다 source+target scanner를 새로 생성하고 multi-app combinations가
증가합니다. 각 app이 자기 private PK-presence와 nullable representation을 복구하는 additive projection scan을
제공하고 runtime이 두 destination slices를 합치는 구조를 채택합니다.

### Existing QuerySet에 public eager field와 composite cache 추가

Normal QuerySet의 `All` return type은 `[]M`이고 joined target/cache를 표현할 위치가 없습니다. Count/Exists/At/
Iterate semantics까지 한 번에 넓히므로 거부합니다. Existing source QuerySet을 입력으로 받는 별도 All-only
`ForwardSelectQuery`를 사용합니다.

### Separate `SelectRelated` aggregate와 `BindSelectRelated`

별도 aggregate는 기술적으로 가능하지만 `Objects`와 같은 project snapshot/model/relation을 다시 binding하고,
사용자가 기능별 binder를 선택하게 만듭니다. Eager 결과가 existing `BlogPostObject`를 반환하므로 별도 ownership
root도 중복입니다. Existing object companion bytes는 유지하고 새 companion이 same-package method를
`BlogPostObjectFactory`에 추가하는 방식을 채택합니다.

### REL-009/010만 구현하고 reverse invalid path는 생략

Typed field만 있으면 invalid reverse가 compile-time absent여서 REL-011 exact runtime taxonomy를 표현하지
못합니다. 반대로 negative parser만 두면 false green입니다. 동일 resolver가 positive typed/dynamic execution과
reverse rejection을 모두 소유하도록 세 contract를 함께 구현합니다.

### Caller가 JOIN kind 또는 target projection을 직접 구성

Nullability와 descriptor field order가 project metadata와 분리돼 corrupt plans를 만들 수 있습니다. Public AST는
resolved one-hop metadata만 담고 binder/compiler가 JOIN kind와 ordered projection을 검증합니다.

## 결정

### Singular immutable relation projection

```go
type RelationProjection struct { /* private */ }

func NewForwardRelationProjection(
	source ir.ModelIdentity,
	sourceTable string,
	sourceKey FieldRef,
	target ir.ModelIdentity,
	targetTable string,
	targetKey FieldRef,
	orderedTargetColumns []FieldRef,
) (RelationProjection, error)

func (p Plan) RelationProjection() (RelationProjection, bool)
func (p Plan) WithRelationProjection(RelationProjection) (Plan, error)
```

`RelationProjection`은 one forward hop과 exact ordered target columns를 clone해 소유합니다. Reverse/multiple-hop/
multiple-projection constructor는 없습니다. Target key는 ordered columns 안의 exactly one non-null integer PK여야
합니다. Plan clone/Equal과 accessors는 deep semantics를 유지합니다. Existing no-projection Plan bytes는 locked입니다.
이미 projection이 있는 Plan에 두 번째 projection을 넣거나 overwrite하는 호출은 zero Plan과
`query_error/invalid_plan`을 반환합니다.

### App-local projection scan

```go
type ProjectionPresence uint8

const (
	ProjectionInvalid ProjectionPresence = iota
	ProjectionAbsent  ProjectionPresence = 1
	ProjectionPresent ProjectionPresence = 2
)

type ProjectionDescriptor[M any] interface {
	ModelDescriptor[M]
	NewProjectionScan() ProjectionScan[M]
}

type ProjectionScan[M any] interface {
	Destinations() []any
	Decode() (M, query.Value, ProjectionPresence)
}
```

Projection companion은 same app package에서 existing named descriptor에 method를 추가합니다. Runtime은 source와
target scan을 매 row 새로 만들고 destinations를 root-first/target-second로 합쳐 `Row.Scan`을 exactly once
호출합니다. Generated scanner는 모든 projected fields를 nullable SQL holder로 받고 private PK-presence를
복구합니다. Decode가 함께 반환하는 PK `query.Value`로 runtime은 reflection이나 v3 target primary-key capability
없이 source FK와 target PK를 대조합니다. Presence zero, partial target row와 non-null field absence는 invalid
shape입니다; all NULL target는 Absent+`query.Null()`, PK와 모든 non-null fields가 있으면 Present+non-NULL integer
key입니다.

### Shared resolver, binder and All-only query

```go
type ForwardSelectPath[S any] struct { /* private */ }
func ResolveForwardSelectPath[S any](BoundModel[S], string) (ForwardSelectPath[S], error)

type ForwardSelect[S, T any] struct { /* private */ }
func BindRequiredForwardSelect[S, T any](
	ForwardSelectPath[S],
	RequiredForwardObject[S, T],
) (ForwardSelect[S, T], error)
func BindNullableForwardSelect[S, T any](
	ForwardSelectPath[S],
	NullableForwardObject[S, T],
) (ForwardSelect[S, T], error)
func (s ForwardSelect[S, T]) Select(QuerySet[S]) ForwardSelectQuery[S, T]

type ForwardSelectQuery[S, T any] struct { /* private */ }
func (q ForwardSelectQuery[S, T]) Plan() query.Plan
func (q ForwardSelectQuery[S, T]) Backend() db.Queryer
func (q ForwardSelectQuery[S, T]) All(context.Context) ([]*ForwardSelected[S, T], error)

type ForwardSelected[S, T any] struct { /* private pointer ownership */ }
func (s *ForwardSelected[S, T]) Source() (S, error)
func (s *ForwardSelected[S, T]) Related() (*RelatedObject[T], error)
```

Resolver accepts one case-sensitive direct forward many-to-one name only. It owns nullability and the canonical AST.
The required/nullable binders derive target identity, descriptor and storage from the already-sealed forward object handle
owned by `BindObjects`; they verify the path and both projection descriptors against that same immutable project snapshot.
They must not call project `Bind` again or reconstruct a target binding. Select preserves the input QuerySet Plan, adds the
projection and creates independent eager evaluation state. It also validates the bound source descriptor dynamic
type/metadata, root table and exact root columns against the path snapshot before I/O; mismatch is a stored
`query_error/invalid_plan` returned by `All`. ForwardSelectQuery is All-only; existing QuerySet remains unchanged. `All`
scans/validates/closes/rechecks context before success-only cache publication. Every return receives source/target clones
and distinct pointer-owned `ForwardSelected` plus ready `RelatedObject`.

Terminal precedence is nil/typed-nil context, existing `ctx.Err`, source QuerySet configuration, nil/typed-nil backend,
zero/corrupt path/binder/descriptors/plan/evaluation, backend/scan/Rows.Err/Close, relationship validation, final context,
publication. Failure returns nil, closes acquired rows once, publishes no partial cache and remains retryable.

### Error taxonomy

```go
const CodeInvalidRelatedPath = "invalid_related_path"
const CodeRelatedObjectProjection = "related_object_projection"
```

Unknown/blank/multi-hop/reverse dynamic path returns `field_error/invalid_related_path`, `Field=<path>`, pre-I/O.
Descriptor/scan shape/forged plan failures are `query_error/invalid_plan`. Required absence, nullable source-key/target
presence disagreement and target PK/source FK mismatch are `integrity_error/related_object_projection`, Field source FK.
Driver/resource/context causes are preserved; Detail is non-contract.

### SQLite projection compiler

SQLite emits root columns then target columns and one qualified join. Required projection is INNER; nullable projection is
LEFT OUTER. Same required edge predicate reuses one join. Root conditions/order/limit retain meaning. Dummy predicate,
second query, reverse join and scanner-guessed column order are prohibited.

### Deterministic generated companions

```go
const RelationProjectionGeneratorVersion = "godj-codegen-rel-projection-v1"
func GenerateRelationProjection(string, ir.Schema) ([]byte, error)

const ProjectRelationSelectRelatedGeneratorVersion = "godj-codegen-rel-select-related-project-v1"
func GenerateProjectRelationSelectRelated(string, []RelationObjectPackage) ([]byte, error)
```

App outputs `zz_godj_relation_projection.go` with generator version/schema SHA. Project output
`zz_godj_relation_select_related.go` does not create a new aggregate or `BindSelectRelated`. It adds
`SelectRelated(QuerySet[blog.Post])` to the existing `BlogPostObjectFactory`; the returned immutable singular builder
exposes typed `Author()`/`Reviewer()` selectors and dynamic direct-path dispatch. Each typed selector returns an opaque
relation-specific All-only query whose `All` publishes existing `[]*BlogPostObject` and warms only that selected private
relation. Original `zz_godj_relation_object.go`, `Objects` and `BindObjects` bytes remain unchanged.

```go
objects, err := project.BindObjects()
selected := objects.BlogPost.SelectRelated(sourceQuery)

posts, err := selected.Author().All(ctx)
posts, err = selected.Reviewer().All(ctx)
dynamic, err := selected.ParseDynamic("author")
posts, err = dynamic.All(ctx)
```

The singular projection does not promise `.Author().Reviewer()` composition. Per-edge opaque query types avoid erasing
different target Go types while keeping `All` output as existing `[]*BlogPostObject`.

`Objects` intentionally contains forward-object sources only. REL-011 does not add a dummy Author factory merely for a
negative example: the conformance gate creates one separately valid project binding, binds Author there, and calls the
same `ResolveForwardSelectPath(..., "posts")` kernel before compiler/DB I/O. That negative-only binding is never mixed
with an eager object/result cache and publishes no application object.

This generated spelling is a bounded low-level bridge for GDJ-0029, not the canonical `project.Using(backend)` facade or
a pre-1.0 public API freeze. Q-017 remains open. A later model-centered facade may delegate to this engine without
changing REL-009/010/011 semantics.

Exact compile union is the prior relationobjectproduct nine generated prerequisites + authors/blog projection companions
two + project select-related companion one = twelve. Old generators/files are byte-locked. Pure generation validates full
input/namespace/gofmt before returning bytes; caller-owned union compile/publication failure preserves last-good output.

## 결과

### 장점

- Joined rows are decoded without changing existing descriptors or QuerySet ABI.
- Required/nullable join kind and reverse rejection share one canonical project resolver.
- Generated typed and dynamic paths converge while returning existing root object wrappers.
- Ready relation access preserves live-context validation and I/O 0 without public cache injection.
- Eager selection reuses one existing object binding instead of introducing another project binder.

### 비용과 제약

- Two app projection files and one project file join the exact nine-file prerequisite union.
- Projection scan and eager cache duplicate some QuerySet lifecycle code intentionally to preserve existing ABI.
- Only one direct relation and All terminal are supported.

## 의도적으로 결정하지 않은 것

Multiple/nested/no-argument eager traversal, canonical application facade, forward/reverse relation-aware chaining,
reverse eager execution, public cross-model target union, OneToOne, non-AutoField PK, Count/Exists/At/Iterate,
annotation/aggregation/distinct, public cache mutation, write invalidation, transactions and non-SQLite backends are
outside this ADR. REL-002/007/008 and REL-012 are unchanged. Q-013 stays Partial and Q-017 stays open.
