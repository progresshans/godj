## 상태와 범위

이 ADR은 **bounded Gate 0 production forward project facade와 additive single-companion first-publication에 한해서
Accepted**입니다. GDJ-0031의 test-only compile feasibility를 production project companion 한 파일로 옮겼고,
exact public 이름, selector representation, generated bytes와 제품 검증을 같은 bounded decision으로 채택했습니다.
Reverse/write facade, REL-002, stable target identity, session expiry enforcement와 general generated upgrade는 이
Accepted 범위에 포함하지 않습니다.

Terminal baseline `3d6612512e8887de8868a319650d54ad0721471b`, activation head `2399cc44...`의
EVID-068/run `31537726792`, implementation head `ba2fa0fa...`의 EVID-069/run `31541883680`은 서로 다른
exact-head hosted gate를 통과했습니다. 어느 run도 이 later completion-documentation tree의 proof로 재사용하지
않으며 이 exact eleven-file tree 자체 CI는 `not run/pending`입니다.

Current product는 unchanged exact 12 adapters/127 contracts=`121 passing + 5 deviation + 1 oracle_locked`, relation
11/12이고 REL-002만 `oracle_locked`입니다. Q-013은 `Partial`, Q-017은 P1/open입니다.

## 맥락

Existing project package는 typed low-level binders, object factories, forward/reverse/prefetch/eager/delete kernel을
제공하지만 application code가 관계마다 `BindObjects`와 `From`을 조립해야 합니다. GDJ-0031은 physical product
fixture를 바꾸지 않은 Go overlay로 one-time project binding, lazy/eager 동일 source wrapper와 forward accessor가
컴파일 가능함을 확인했습니다. Candidate가 overlay 없이는 실패하도록 해 product support와 feasibility를 분리했습니다.

다음 단계는 low-level kernel을 감춘 additive project facade를 실제 generated output으로 처음 게시하는 것입니다.
다만 test-only candidate 이름을 그대로 채택하거나 existing generated 13 files를 함께 다시 쓰면 API와 upgrade
정책을 검증하기 전에 surface를 동결합니다. 따라서 production 경계를 좁히고 이름 결정과 publication 실패 의미를
먼저 고정해야 합니다.

## 결정 기준

- Existing generated exact 13 bytes와 current product behavior를 보존
- Global default 없이 explicit backend/session origin 사용
- 모든 declared model에 import-cycle-free project-owned wrapper/query root 제공
- Raw app model, low-level Object와 application wrapper 역할을 타입으로 분리
- Required/nullable forward 관계가 같은 target wrapper namespace를 사용
- Lazy/eager가 같은 source wrapper/accessor와 existing cache kernel을 사용
- Author/Reviewer를 하나의 selector/eager abstraction으로 처리
- Capability 요구가 실제 facade 범위보다 넓거나 좁지 않음
- Deterministic name/collision과 single-file publication failure가 fail-closed
- Compile/runtime/product proof와 unimplemented reverse/REL-002/upgrade 범위를 분리

## 결정

### Additive project-only companion

Existing exact 13 generated files는 byte-for-byte 고정합니다. 새 generator는 project package의
`zz_godj_relation_facade.go` companion 하나만 생성합니다. 이 packet은 missing target의 first publication과 같은
target의 replacement만 다루며 coordinated multi-file upgrade를 주장하지 않습니다.

### Project-local capability composite

Facade origin은 project-local interface로 `db.Queryer`와 `db.Mutator`를 embed합니다. `db.RelationAtomic`은 포함하지
않습니다. Concrete backend 또는 callback-local session이 두 method set을 만족하면 사용할 수 있지만, 정적 타입이
`db.Queryer`인 값은 전달할 수 없어야 합니다. Queryer+Mutator만 구현한 minimal fake와 `db.Session`은
`db.RelationAtomic`/`db.RelationMutator` 없이 positive여야 합니다.

Construction은 `BindObjects`를 먼저 검증합니다. Binder failure와 nil/typed-nil backend가 함께 있으면 original
binder error/cause가 우선하고, valid binding 뒤 nil/typed-nil backend는 `backend_error/invalid_plan`입니다. 둘 다
I/O 0입니다. Invalid category/code는 stable하고 detail message는 noncontractual입니다. Exact interface/entrypoint
이름만 implementation 전 decision gate에 남깁니다.

### Project-owned wrappers for every declared model

모든 declared model은 project-owned pointer wrapper와 all-model query root를 가집니다. Target model의 query root와
forward accessor는 같은 wrapper type을 반환하며 현재 Author와 Reviewer는 둘 다 Author query root의 target wrapper
type을 사용합니다.

- Required relation: `(*TargetWrapper, error)` shape
- Nullable relation: `(*TargetWrapper, bool, error)` shape; SQL `NULL`은 `nil, false, nil`
- Raw app model은 explicit unwrap으로만 반환
- Existing low-level `*...Object`와 새 wrapper의 exported namespace/identity는 disjoint
- Nil/zero/dereference-copy wrapper와 zero aggregate/query root는 `query_error/invalid_plan`, I/O 0으로 거부;
  detail message는 noncontractual

Stable pointer identity는 이 결정의 일부가 아닙니다. 별도로 materialize하거나 반복 accessor가 만든 target wrapper의
pointer equality와 downstream target-wrapper cache/identity-map 의미는 후속입니다.

### Common forward selector and stored eager query

Author-only special case 대신 모델별 common sealed selector가 `Author`와 `Reviewer`를 모두 표현합니다. Query 하나는
정확히 하나의 direct one-hop forward edge만 선택합니다. Eager query wrapper는 선택된 concrete low-level eager
query/evaluation state를 저장해 `All`마다 새 evaluation cache를 만들지 않습니다. Eager 결과는 warm relation cache를
가진 low-level source object pointer를 보존한 채 source project wrapper로 감쌉니다.

Author와 Reviewer 선택은 Filter/OrderBy/Limit 전후 모두 edge를 보존하고 required present, nullable present/NULL을
검증합니다. Eager query의 value copy와 반복 terminal은 한 evaluation state를 공유하지만 derived chain은 독립
evaluation state를 가집니다. Gate 0는 exported sealed `BlogPostRelationSelector`,
`BlogPostRelationSelectors` aggregate와 unexported discriminator representation을 고정했습니다. Public typing이 일부
misuse를 compile-time에 막더라도 internal adversarial seam은 nil/typed-nil/zero/cross-model selector와 zero eager query를
모두 구성하며 결과는 `query_error/invalid_plan`, I/O 0이고 detail message는 noncontractual입니다.

Source cache는 source wrapper-scoped입니다. 같은 source wrapper의 accessor/eager warm state는 공유하지만 별도
source/target wrapper, target pointer identity나 downstream target cache 공유는 계약하지 않습니다.

### Generator fixture breadth

Generator는 current two-model fixture 외에 unrelated model, multi-app/multi-model permutation,
target-also-relation-source와 self-edge project를 deterministic generate/compile해야 합니다. 이는 all-model wrapper와
one-hop edge construction proof이며 multi-hop runtime/chaining support가 아닙니다.

Existing relation-object prerequisite가 unrelated model을 bind한 뒤 generated source에서 사용하지 않아 compile되지
않는 경우에는 해당 bind 결과를 명시적으로 consume하는 최소 prerequisite correction을 함께 허용합니다. Binding
validation과 공개 API는 유지하고 current product exact 13 generated bytes가 byte-identical임을 별도 gate로 둡니다.

### Origin and callback lifetime

Facade/query/wrapper는 origin lifetime 안에서만 사용합니다. Session-origin facade는 callback 내부만 지원합니다.
Current interface는 callback 뒤 expiry를 항상 검사할 수 없고 warm cache는 backend I/O 없이 성공할 수 있으므로,
callback 이후 deterministic failure나 continued validity를 계약하지 않습니다. Strong lifetime capability는 별도 ADR
대상입니다.

### Deterministic names and collisions

Implicit English pluralization은 사용하지 않습니다. App alias prefix와 model Go name의 singular surface를 사용하며
Gate 0에서 다음 exact surface를 implementation decision으로 고정했습니다.

- `type Backend interface { db.Queryer; db.Mutator }`
- `func Using(Backend) (Models, error)`
- `Models{AuthorsAuthor AuthorsAuthorQuery, BlogPost BlogPostQuery}`
- Project wrappers `AuthorsAuthor`, `BlogPost`와 roots `AuthorsAuthorQuery`, `BlogPostQuery`
- Sealed `BlogPostRelationSelector`, aggregate `BlogPostRelationSelectors`, stored-state `BlogPostEagerQuery`
- Raw clone `Unwrap`, ordered `First(ctx) (*Wrapper, bool, error)`, `Limit(int) (Query, error)`

Selector aggregate의 `Author`/`Reviewer`는 같은 sealed interface와 unexported discriminator를 사용하며 외부 구현은
허용하지 않습니다. App alias, model Go name과 explicit normalized naming input으로 이름을 만들고 existing/new project
declarations 전체와 collision을 검사합니다. Handwritten project source collision은 exact candidate-union compile을
최종 방어선으로 둡니다.

### First-publication failure semantics

Check mode는 expected/current byte 동일성만 비교하며 Verify를 실행했다고 표현하지 않습니다. Write mode는
same-directory temp write/sync, whole candidate package Verify 성공, 단일 rename 순서로 게시합니다. First publication
Verify 실패는 target absent, replacement 실패는 last-good preserved여야 합니다. Directory fsync, multi-file atomicity,
rename/deprecation/repair는 이 결정 밖입니다.

## 고려한 선택지

### Existing low-level Object를 application wrapper로 노출

추가 타입은 적지만 project query root와 target chaining의 ownership을 표현하지 못하고 low-level binding surface를
canonical API로 고정합니다. 거부합니다.

### Test-only overlay를 그대로 유지

Feasibility evidence는 보존하지만 실제 application import에 surface가 존재하지 않습니다. GDJ-0031에서는 맞았지만
이 production packet의 목표를 충족하지 못합니다.

### Query-only `db.Queryer`를 facade input으로 사용

Read-only compile에는 충분하지만 같은 facade origin의 mutation-capable project 경계를 다시 깨뜨립니다. Project-local
Queryer+Mutator composite를 채택하고 정적 Queryer-only 입력을 negative gate로 둡니다.

### RelationAtomic까지 요구

Forward read-only query/accessor에 필요하지 않고 session/backend 구현을 과도하게 제한합니다. 이번 capability에서
제외합니다.

### Existing generated files와 함께 facade를 재생성

한 번에 정리할 수 있지만 frozen exact 13과 additive compatibility proof를 잃고 general multi-file upgrade 문제를
숨깁니다. 새 companion first-publication만 허용합니다.

## 의도적으로 결정하지 않은 것

- Reverse manager/chaining, multiple/nested/reverse eager와 target wrapper의 stable pointer identity
- Target wrapper downstream relation cache 또는 identity map
- REL-002 assignment/save/cache invalidation과 unsaved related object 의미
- Write/delete facade, callback 이후 session lifetime enforcement
- Wrapper JSON/scalar promotion/custom model methods
- General generated upgrade, CLI, rename/deprecation/repair와 multi-file atomicity
- PostgreSQL/MySQL/Windows product support

## 검증

- Existing exact 13 before/after byte lock과 new companion independent inventory
- Schema/model/relation ordering permutation과 unrelated/multi-app/multi-model/target-source/self-edge fixture의
  deterministic generator/golden/compile
- All-model query root/wrapper와 required/nullable same-target-wrapper compile/runtime gate
- Raw model/low-level Object 반환 및 wrapper-name collision negative gate; external AST는 Save/Delete/reverse와
  low-level Object re-exposure를 거부
- Minimal Queryer+Mutator/`db.Session` positive, static Queryer negative, RelationAtomic/RelationMutator absence proof
- Nil/typed-nil backend와 binder-error precedence/category/code/I/O-0 gate
- Author/Reviewer common selector, before/after Filter/OrderBy/Limit와 stored eager evaluation/cache proof
- Lazy first/second access query count, eager zero-extra-query와 nullable NULL no-query
- Copied/repeated eager shared evaluation, derived chain independence와 source-wrapper-scoped cache
- Nil/typed-nil/zero/cross-model selector, zero aggregate/root/eager와 nil/zero/copy wrapper pre-I/O error;
  explicit raw-model clone/unwrap
- Callback-local session use와 post-callback non-contract documentation gate
- Missing/drift/Verify failure/last-good preservation
- Overlay removal, production no-overlay external compile와 exact inventory/workflow self-check
- Separate activation/implementation/completion/terminal exact-head evidence

## 결과

이 ADR이 승인하는 것은 existing low-level kernel 위에 Gate 0 exact surface의 project-only forward facade
companion 하나를 additive first-publish하는 bounded architecture입니다. Existing generated exact 13은 byte-identical로
보존됐고 additive generated exact 14와 physical exact 17이 EVID-069에서 검증됐습니다. Gate 0 이름은 이 bounded
facade에서 canonical입니다. Reverse/REL-002/general upgrade/session-expiry 보장은 후속으로 남깁니다.
