# ADR-0035: Pre-release Current-only Format and Generated ABI Reset

- 상태: Accepted
- 날짜: 2026-08-20
- 관련 work/contract: [GDJ-0036](../../work/0036-pre-release-compatibility-reset.md), Q-010, Q-012, Q-013, Q-017
- 대체하는 ADR: ADR-0019, ADR-0020, ADR-0024, ADR-0031, ADR-0032, ADR-0034

## 맥락

GoDj는 아직 외부 alpha/release가 없고 저장소에도 release tag나 지원해야 할 사용자 migration/generated ABI가 없습니다.
그런데 개발 중 scalar 형식과 뒤이은 relation 형식을 이미 배포된 두 세대처럼 동시에 유지하면서 Definition profile,
digest, ProjectState, backend begin entry와 generated publication이 이중화됐습니다. 이 분기는 D4g 이후 operation,
PostgreSQL과 full-stack metadata에 곱해질 수 있습니다.

버전 필드, historical state와 deterministic output은 안전성에 필요합니다. 문제는 version 숫자가 아니라 첫 공개 기준점
이전의 untagged snapshot을 영구 reader/API/byte compatibility 대상으로 만든 것입니다.

## 결정 기준

- 첫 공개 사용자 경험보다 앞선 내부 snapshot을 지원하지 않을 것
- persisted data와 destructive migration의 integrity는 약화하지 않을 것
- package import cycle 없이 loaded authority를 명시적으로 표현할 것
- scalar와 relation을 동일한 current model/migration pipeline으로 처리할 것
- 과거 generated bytes가 아니라 현재 schema snapshot과 generator ABI를 재현성 기준으로 삼을 것
- Django observable behavior compatibility와 GoDj 과거 내부 ABI compatibility를 분리할 것

## 고려한 선택지

### 기존 additive compatibility 계속 유지

이미 검증된 bytes와 API를 보존하지만, 새 기능마다 profile/state/backend/generator 분기가 늘고 공개 전부터 upgrade matrix가
고정됩니다. 채택하지 않습니다.

### 버전 숫자만 다시 1로 변경

표면은 단순해지지만 구 reader, context carrier와 이중 backend entry를 남기면 복잡성은 사라지지 않습니다. 숫자 변경만으로는
충분하지 않습니다.

### Current-only flag-day reset

Git history와 과거 증거는 보존하되 제품 코드에서는 current reader/state/API/generated ABI 하나만 유지합니다. 기존 SQLite
transaction/rollback/restart 의미를 회귀 기준으로 재사용할 수 있고 첫 외부 기준점 전에 비용이 가장 낮습니다. 채택합니다.

## 결정

1. 첫 외부 alpha 이전 untagged Schema IR, Migration Definition, ProjectState와 generated output은 지원 대상이 아닙니다.
2. Schema IR은 scalar와 ForeignKey를 함께 표현하는 current format 하나를 사용합니다. 명시적 version과 unknown-version
   fail-closed는 유지합니다.
3. Migration Definition wire는 format_version 하나와 current operation shape를 사용합니다. Loader ABI, operation codec,
   Schema IR 숫자를 독립 persisted compatibility tuple로 노출하지 않습니다.
4. Canonical digest domain은 current definition shape 하나만 가집니다.
5. Historical ProjectState는 current IR 하나를 담고 format promotion/demotion을 하지 않습니다. Historical replay, clone,
   graph, restart는 유지합니다.
6. definition.Load는 root-owned opaque migrations.LoadedDefinitionSet을 반환하고 Executor.Migrate는 그 값만 받습니다.
   Raw []Migration과 hidden context handoff를 product execution authority로 사용하지 않습니다.
7. Migration backend는 mandatory MigrationCapabilities와 하나의 BeginMigration(HistoryTransition, MigrationIntent)을
   사용합니다. Scalar intent는 relation target이 비어 있을 수 있습니다. SQLite FK-on, physical preflight와 remake 분기는
   sealed intent에 따른 backend 내부 실행 경계로 남습니다.
8. Codegen은 app-owned model과 project-owned cross-app binding 책임을 유지하되, 과거 파일 bytes를 보존하기 위해 새 companion만
   추가하는 정책을 폐기합니다. 현재 generator와 checked-in app/project output set을 하나의 current ABI로 재기준화합니다.
   Project-level manifest, 전체 candidate compile과 coordinated publication/repair는 Q-017의 후속 제품 작업이며 이번 reset이
   구현됐다고 주장하지 않습니다.
9. 첫 외부 alpha를 명시적으로 선언한 시점부터 새 compatibility policy를 작성합니다. 그 전 형식에는 reader나 upgrader를
   제공하지 않습니다.

## 계승하는 안전성 결정

- strict decoding, resource limit, immutable snapshot, provenance와 graph integrity
- canonical digest와 deterministic error
- historical reconstruction, recorder, revision fence, rollback과 commit durability tri-state
- backend capability, structured unsupported error와 no silent fallback
- pinned SQLite connection, FK enforcement, D4d~D4f physical preflight/remake/row/sequence preservation
- deterministic codegen, schema hash, gofmt, 현재 per-file candidate compile와 last-good preservation
- Django reference/product/deviation/status의 truthful separation

## 결과

기존 development fixture와 generated golden은 current shape로 한 번 재생성해야 하고, 과거 tuple/digest/byte identity를 직접
계약화한 MIG-075~078은 retire하거나 새 current-format invariant ID로 재정의해야 합니다. D4d~D4f 제품 동작과 MIG-079~086의
독립적인 transaction/DDL 관찰은 새 구조의 회귀 자료로 사용할 수 있지만 자동으로 passing을 뜻하지 않습니다.

이 결정은 breaking change입니다. 외부 release가 없는 pre-release reset이므로 compatibility shim을 추가하지 않습니다.

## 의도적으로 결정하지 않은 것

- PostgreSQL 또는 non-SQLite migration compiler
- public migration writer/autodetector와 upgrade tool
- general generated file layout과 사용자-facing CLI naming
- project-level codegen manifest와 app/project 전체 candidate의 coordinated publication/repair
- first alpha 이후의 semver/format support 기간
- broader Field, Relation, Web, Form, Auth, Admin, API 범위

## 검증

- current-only document/IR의 canonical digest, strict error와 resource-bound tests
- scalar/relation mixed full-plan reconstruction과 execution rematerialization seal equality
- D4d nullable Add, D4e empty-source required Add, D4f bounded Remove/remake actual SQLite regression
- rollback, recorder failure, commit outcome, restart/no-op/reapply와 race/CGO0/386
- current generated app/project output set의 deterministic regeneration, external consumer compile와 per-file last-good preservation
- 최종 frozen tree 한 번의 full local/hosted integration gate
