# 테스트와 검증 코드 공통화

동일한 보조 구현과 fixture 준비를 공유해 수정 지점과 코드량을 줄인다. 테스트가 잡아내는 결함,
실패 진단, 실행 환경과 상태 격리를 유지한다. 감축률 자체를 목표로 검증을 제거하지 않는다.

## 범위와 결정

- `conformance/`의 프로세스 보조 코드, 관계 fixture·generated drift 준비, protocol/runner 테스트의 반복 준비가 대상이다.
- 같은 의미를 확인한 구현만 공통화한다. 명령별 오류·timeout 정책, DB 부작용·취소·child reap 시나리오는 유지한다.
- fixture는 호출마다 새 입력을 만들며, GoDj actual과 Django expected/oracle은 구현을 공유하지 않는다.
- 내부 필드·호출 위치의 개수 검사는 해당 위험의 실제 동작 검증을 확인한 경우에만 정리한다.
  generated bytes/inventory, provenance, dependency 경계와 false-green 부정 검증은 유지한다.
- 수정 허용 경로는 `conformance/`, 필요한 검증 연결의 `Makefile`·CI 도구, 이 작업과 현행 상태·검증 문서다.
  제품 API·runtime·생성 ABI·고정 oracle/profile은 변경하지 않는다.

- [x] 관련 normal/race/CGO-disabled, generated drift·외부 consumer 검증

## 검증

편집 중 affected package와 관련 drift를 실행한다. 통합 checkpoint에서 공통 helper 소비자의 normal/race/
CGO-disabled와 실제 process 회귀를 확인한다. 최종 고정 소스의 Hosted full scope가 플랫폼·PostgreSQL·reference와
cold/external 검증을 소유한다. 같은 전체 matrix를 로컬에서 중복 실행하지 않는다. source 변경으로 실패를 보정하면
새 exact head의 해당 검증을 다시 확인한다. 문서-only 완료 기록에는 문서·diff 검사를 적용한다.

실제 실행 결과와 source는 [TEST_EVIDENCE](../docs/status/TEST_EVIDENCE.md)에 기록한다.
