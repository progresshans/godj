# GDJ-0053 — Project Relation-query Sparse-model Compile Availability

## 사용자에게 보이는 결과

현재 public Schema/ProjectSpec만 사용한 프로젝트에 required ForeignKey relation-query source와 함께 relation-query surface가
없는 scalar-only 모델 또는 nullable-only relation target이 있어도 `godj generate` candidate 전체가 Go compile을 통과합니다.

기존 required relation selector, model binding validation, 오류 순서, generated role/file roster와 공개 API는 바뀌지 않습니다.

## 목표

- Required relation-query source/target과 무관한 project model 때문에 생성된 `_modelN` local이 unused가 되어 whole-candidate
  compile이 실패하는 경로를 회귀 테스트로 먼저 재현합니다.
- Required relation source가 존재하는 기존 mixed path에서는 모든 project model의 `orm.BindModel` 호출과 오류 검증을
  canonical identity order로 유지합니다. Scalar-only/no-required-source fast path는 계속 model local을 만들지 않습니다.
- 성공적으로 bind했지만 required relation-query assembly에서 사용하지 않는 model local만 `_ = _modelN`으로 명시적으로
  소비합니다.
- Existing all-used project golden과 current example generated bytes를 byte-identical하게 보존합니다.
- Scalar-only, required relation + unrelated scalar model, required relation + otherwise-unused nullable-only target의 서로 다른
  project shape를 실제 외부 module compile로 검증합니다.

## 비목표

- Nullable ForeignKey typed relation-query selector 추가 또는 required-only surface 확대
- Unused model의 `BindModel` 생략, lazy binding, model filtering 또는 validation/error-order 변경
- Schema IR, Query AST, migration definition/state, backend/compiler와 transaction 변경
- Generated role/file roster, generator version, manifest ABI, public symbol 또는 facade 이름 변경
- Golden 일괄 재기준화, 현재 example bundle rewrite 또는 compatibility reset
- Form/Admin/API second-model 일반화, scaffold CLI, `sqlmigrate`, JWT/OAuth, Realtime
- 새로운 Django/DRF contract, deviation 또는 product aggregate status 변경

## Django Reference / Contract

- 이 결함은 Django observable parity가 아니라 Go generated-source compile availability입니다. Django/Python source나 oracle을
  새로 실행하지 않습니다.
- 기존 GEN-M1-001의 deterministic generated source와 Q-017의 candidate-compile/publication 경계를 authority로 사용합니다.
- Passing 의미는 public-only external module의 candidate가 Go compile되고 existing golden/version/role ABI가 drift하지 않는 것입니다.

## 설계와 가설

`renderBindRelations`가 generation 시점에 다음 exact used set을 계산합니다.

```text
used model bind indexes
  = every required relation source
  ∪ every required relation target
```

모든 model은 기존처럼 canonical order로 `BindModel`하고 `_err`를 확인합니다. 그 뒤 used set에 없는 model에만
`_ = _modelN`을 생성합니다. 따라서 validation coverage는 축소되지 않고 Go compiler의 unused-local 규칙만 충족합니다.

Nullable relation은 현재 relation-query surface에서 의도적으로 제외되므로 그 target이 다른 required edge에 쓰이지 않으면 unused
binding입니다. 이를 required selector로 승격하지 않고 blank-consume하는 것이 이번 bounded fix입니다.
