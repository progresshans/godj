# AutoField ForeignKey Schema IR vNext, Atomic Project Binding, and REL-001 Product Metadata

## 사용자에게 보이는 결과

완료 후 사용자는 AutoField primary key를 target으로 하는 cross-app `ForeignKey` 두 개를 Schema DSL에
선언하고, generated source model의 FK scalar storage와 project-level binding을 통해 forward/reverse
runtime metadata를 얻을 수 있습니다. `blog.Post.author`와 nullable `blog.Post.reviewer`는 target app
generated package를 직접 import하지 않으며, 하나의 atomic project binding 결과에서 각각
`authors.Author.posts`와 `authors.Author.reviewed_posts` reverse metadata를 파생합니다.

이번 제품 단면은 REL-001 metadata만 구현합니다. Relation lookup, lazy object load/cache, assignment/save,
delete policy execution, `select_related`, `prefetch_related`, FK DDL 또는 relation migration은 제공하지
않습니다. 완료 분류는 existing `110 passing + 5 deviation`에 REL-001 하나만 더한
product `12 adapter sets/127 contracts = 111 passing + 5 deviation + 11 oracle_locked`입니다. Relation actual
coverage는 1/12입니다.

## REL-001 exact 제품 계약

REL-001의 locked oracle/phase/comparison/provenance를 다시 쓰지 않습니다. Actual 제품 observation은 actual
Schema DSL → relation-capable IR → generated app companions/project bridge → atomic binder → runtime metadata
경로만 읽어 다음 result를 구성합니다.

```text
forward:
  blog.post.author   -> name=author, column=author_id, target=authors.author, nullable=false,
                        many_to_one=true, reverse=posts, on_delete=PROTECT
  blog.post.reviewer -> name=reviewer, column=reviewer_id, target=authors.author, nullable=true,
                        many_to_one=true, reverse=reviewed_posts, on_delete=SET_NULL
reverse:
  authors.author.posts          -> name=posts, field=author, target=blog.post, one_to_many=true
  authors.author.reviewed_posts -> name=reviewed_posts, field=reviewer, target=blog.post, one_to_many=true
```

- Required/nullable FK scalar storage는 각각 `int64`/`*int64`이고 target object cache/loader가 아닙니다.
- 두 forward와 두 derived reverse projection은 같은 immutable bound edge source에서 나와야 합니다.
- Metadata observation에는 DB open/query/schema/write/mutation이 0이어야 합니다.
- Actual adapter가 oracle/static fixture 또는 expected REL-001 constant를 읽거나 재생하면 실패입니다.
- Adapter presentation은 actual metadata의 exact IR tokens `protect`/`set_null`을 각각 oracle enum spelling
  `PROTECT`/`SET_NULL`로 명시적으로 변환하며 expected fixture를 읽거나 replay하지 않습니다.
- Source field/target/reverse/nullability/delete policy mutation은 actual observation 또는 binding failure를
  바꾸고 `protocol.Compare` diff를 만들어야 합니다.

## Schema IR vNext와 v2 불변

`ir.FormatVersion=2`는 바꾸지 않고 relation-capable exact version은
`ir.RelationFormatVersion=3`입니다. `ir.Normalize`, `CanonicalJSON`, `Hash`는 version-aware가 되며 zero
format은 기존처럼 v2로 normalize하고 exact 2 또는 3만 받습니다. V2 field는 relation arm을 거부하고
기존 canonical JSON/hash/golden과 `godj-codegen-m2-v3` output을 byte-for-byte 보존합니다. V3는 기존 scalar
field tag를 그대로 허용하고 다음 explicit arm만 추가합니다.

```go
const FieldForeignKey FieldKind = "foreign_key"

type ModelIdentity struct {
	AppLabel  string `json:"app_label"`
	ModelName string `json:"model_name"`
}

type Field struct {
	// existing v2 fields remain unchanged
	Relation *ForeignKeyRelation `json:"relation,omitempty"`
}

type ForeignKeyRelation struct {
	Target      ModelIdentity       `json:"target"`
	Cardinality RelationCardinality `json:"cardinality"` // exact many_to_one
	Reverse     ReverseRelation     `json:"reverse"`     // name xor disabled:true
	OnDelete    DeletePolicy        `json:"on_delete"`   // protect or set_null
}

type RelationCardinality string
type DeletePolicy string

const (
	RelationManyToOne RelationCardinality = "many_to_one"
	RelationOneToMany RelationCardinality = "one_to_many"
	DeleteProtect     DeletePolicy        = "protect"
	DeleteSetNull     DeletePolicy        = "set_null"
)

type ReverseRelation struct {
	Name     string `json:"name,omitempty"`
	Disabled bool   `json:"disabled,omitempty"`
}
```

Physical `Column`, `GoName`와 `Nullable`은 source `Field`가 소유합니다. ForeignKey는
`PrimaryKey=false`, `MaxLength=0`, `Default=nil`이어야 합니다. Target identity는 normalized
`(app_label, model_name)`이고 source spelling/import alias/Go type pointer와 무관합니다. Target의 exact
model 존재는 project binder가 resolve하지만 각 target schema의 AutoField-only key shape는
`ir.Normalize`가 먼저 강제합니다. Required/nullable storage는 각각 `int64`/`*int64`입니다.

IR exact token constants는 `RelationManyToOne="many_to_one"`,
`RelationOneToMany="one_to_many"`, `DeleteProtect="protect"`,
`DeleteSetNull="set_null"`입니다. `ReverseRelation`은 exact
`{Name string json:"name,omitempty"; Disabled bool json:"disabled,omitempty"}`이고 두 값 중 정확히 하나만
활성입니다.

`func (f ir.Field) Clone() ir.Field`는 `Default`와 `Relation` nested state를 모두 deep-copy하고
`Model.Clone()`은 모든 field에 이를 사용합니다. Schema normalization, binder input, generated companion,
`ExecutePlan` retained plan, `NewStateReconstructor`/lifecycle definition snapshot과 `migrations/definition` clone은
caller-owned relation pointer를 보존하면 안 됩니다. Direct `Executor.Apply`/`Unapply` alias/race semantics는
그대로이며 이번 packet 범위 밖입니다.

모든 snapshot/clone API의 caller는 call이 진행되는 동안 input을 concurrent mutation하지 않아야 합니다.
Deep-copy는 unsynchronized concurrent writer를 race-free로 만드는 장치가 아닙니다. Successful snapshot/return
뒤 caller mutation은 retained value에 영향을 주지 않고, published `ProjectBinding`의 concurrent read/accessor는
race-safe합니다. Mutation/race tests도 post-snapshot caller mutation과 concurrent binding reads를 검증하며
call 도중 arbitrary input writer를 허용하지 않습니다.

DSL의 exact surface는 다음입니다.

```go
schema.ModelTarget{AppLabel: "authors", ModelName: "author"}
schema.Target("authors", "author")
schema.RelatedName("posts")
schema.NoReverse()
schema.Protect
schema.SetNull

schema.ForeignKey(
	"author", "AuthorID",
	schema.Target("authors", "author"),
	schema.RelatedName("posts"),
	schema.Protect,
)

schema.ForeignKey(
	"reviewer", "ReviewerID",
	schema.Target("authors", "author"),
	schema.RelatedName("reviewed_posts"),
	schema.SetNull,
	schema.Nullable(),
)
```

`schema.ModelTarget`, `schema.ReverseRelation`과 `schema.DeletePolicy`는 각각 exact aliases
`type ModelTarget = ir.ModelIdentity`, `type ReverseRelation = ir.ReverseRelation`,
`type DeletePolicy = ir.DeletePolicy`입니다. Constructors는 exact
`func Target(appLabel, modelName string) ModelTarget`,
`func RelatedName(name string) ReverseRelation`, `func NoReverse() ReverseRelation`이고 exact delete constants는
`Protect`/`SetNull`입니다. Public `schema.Field`에는
`Relation *ir.ForeignKeyRelation`이 추가되며 `schema.Build`는 이를 deep-copy한 뒤 normalize합니다.
`ForeignKey(name, goName string, target ModelTarget, reverse ReverseRelation, onDelete DeletePolicy,
options ...FieldOption) Field`가 exact constructor입니다. `schema.Build`는 ForeignKey가 하나라도 있으면
v3을, scalar-only definition에는 계속 v2를 생성합니다. ForeignKey의 기본 physical column은 options를
적용하기 전 exact `name + "_id"`이고 `schema.Column(...)`이 이를 명시적으로 override합니다. Direct v3
`ir.Schema`도 foreign-key `Column`이 empty이면 `ir.Normalize`가 exact `field.Name + "_id"`로 기본화하고
explicit Column은 보존합니다. Scalar v2의 empty Column은 기존 `field.Name` 규칙과 bytes를 그대로 유지합니다.

Relation arm과 scalar field state의 혼합, invalid target/key/cardinality/delete policy/reverse state와 invalid
nullability-policy pair는 canonical field path를 가진 deterministic validation error여야 합니다. Map
iteration, post-normalization input alias mutation과 canonical encoder round-trip이 ordering/hash를 바꾸면 안 됩니다. 이번
packet은 새 public raw JSON decoder를 만들지 않으므로 unknown-key/duplicate-key decode semantics를
relation IR 지원으로 주장하거나 고정하지 않습니다.

## Codegen과 project bridge

- `codegen.Generate`는 normalized format을 검사합니다. V2 branch는 existing `GeneratorVersion =
  "godj-codegen-m2-v3"`와 output bytes를 문자 그대로 보존합니다. V3 branch는 source model의
  `int64`/`*int64` FK scalar fields를 가진 plain model structs만 생성하고 distinct
  `RelationGeneratorVersion = "godj-codegen-rel-v1"`을 사용합니다. V3 main generated exported surface는 exact
  `GoDjGeneratorVersion = "godj-codegen-rel-v1"`, `GoDjSchemaSHA256`와 plain model structs/fields뿐입니다.
  Relation IR/schema accessor는 companion-only입니다. V3 output에는 `db`, `query`,
  `Manager`, `WriteDescriptor`, relation query selector/loader 또는 relation create/update API symbol이 없어야
  합니다.
- REL-001 project는 v2 scalar target-only `authors`와 v3 relation-source `blog`를 함께 bind합니다. Existing
  authors main generated bytes를 바꾸지 않고 모든 participating app에 exact additive
  `codegen.GenerateRelationMetadata(packageName string, input ir.Schema) ([]byte, error)` companion을
  생성합니다. Companion은 exact generated symbols
  `GoDjRelationMetadataGeneratorVersion = "godj-codegen-rel-v1"`과
  `GoDjRelationSchemaSHA256`, fresh deep-copy를 반환하는 exported `GoDjRelationSchema() ir.Schema`를 v2
  target-only/v3 source 모두에 동일하게 제공합니다. V3 main+companion same-package compile은 필수입니다.
- Project bridge input은 exact `type BridgePackage struct { Alias string; ImportPath string }`이고
  `codegen.GenerateProjectBridge(packageName string, packages []BridgePackage) ([]byte, error)`가 canonical
  alias/import order의 source를 만듭니다. Bridge provenance version은
  `godj-codegen-rel-project-v1`이고 exact generated symbol은
  `GoDjProjectBindingGeneratorVersion`입니다.
- Generated bridge는 app packages와 `orm`만 import하고 exported
  `Bind() (orm.ProjectBinding, error)`에서 `orm.BindProject(app.GoDjRelationSchema()...)`를 호출합니다. Bridge가
  raw DSL/JSON을 읽거나 target/reverse metadata를 수동으로 복제하지 않습니다. Generator binary 자체는
  generated target을 import하지 않습니다.
- Normalized schema hash와 해당 generator version이 generated provenance에 들어갑니다.
- Same input의 output은 byte-identical/gofmt이며 unrelated app/model/input order 변화가 canonical result를
  비결정적으로 바꾸지 않습니다.
- `Generate`, `GenerateRelationMetadata`와 `GenerateProjectBridge`는 deterministic bytes만 반환합니다.
  Completion tests는 multi-app main/companion/bridge candidate bytes 전체를 generation/format/compile/bind하고,
  어느 candidate validation failure에서도 미리 존재하던 committed output sentinel이 전혀 바뀌지 않음을
  검증합니다. 이는 validation path의 no-write 보장일 뿐 product publication 또는 rollback
  API가 아닙니다. Existing single-file `WriteFile` semantics/bytes는 변경하지 않습니다. Caller publication,
  atomic project-set writer, CLI generate/check와 replacement/rollback/crash consistency는 후속 bounded packet이
  소유합니다.
- Mutual `authors ↔ blog`와 self relation external module은 `go list`/`go test`를 통과하고 generated
  app-to-app import edge는 exact 0이어야 합니다.
- Dedicated `conformance/relationproduct/**`는 checked-in generated `authors`/`blog` main+companion files와 project bridge,
  그리고 그 bridge를 실제 import해 `Bind()` metadata를 반환하는 observer를 소유합니다. Fixture는 declaration
  schema에서 regenerate한 candidate bytes와 byte-equal이고 검증은 tracked output을 rewrite하지 않습니다.
  GoDj relation adapter는 이 observer만 호출해 actual REL-001 payload를 만들며 oracle/static fixture/expected
  constants를 읽지 않습니다. 별도 external mutual/self compile fixture가 import edge 0을 검증합니다.

Typed relation query selector와 loader는 이번 work에서 생성하지 않습니다. Generated scalar FK storage와
metadata bridge가 query/write/eager 지원을 뜻하지 않습니다.

## Atomic project binding과 error 경계

Binder는 app마다 정확히 하나의 schema를 받으며 다음 순서를 하나의 all-or-nothing value operation으로
수행합니다.

```text
snapshot one schema per app and all model/source relations
→ reject duplicate app inputs; validate normalized source fields/columns
→ resolve every symbolic target and AutoField key
→ derive forward/reverse candidates
→ validate relation identity and reverse namespace collisions
→ publish one immutable binding set
```

- Successful snapshot 뒤 input slices/maps/pointers는 caller의 post-call mutation과 alias하지 않습니다.
- 어느 validation에서도 실패하면 accessible partial set/forward/reverse projection은 0입니다.
- `ForwardRelations`는 exact `(Source.AppLabel, Source.ModelName, Field)`, `ReverseRelations`는 exact
  `(Owner.AppLabel, Owner.ModelName, Name)` 순입니다. `Relation` lookup은 input order와 무관합니다. Duplicate-app
  precheck 뒤 first error도 같은 canonical source-relation order를 사용합니다.
- Zero value/empty project, duplicate app input과 conflicting input의 exact meaning을 test로 고정합니다.
- Success 결과 accessor가 내부 slice/map을 노출하지 않으며 concurrent read/race와 caller output mutation을
  격리합니다.
- Global mutable registry, `init()` registration, reflection-based target discovery와 incremental publication은
  금지합니다.

Reverse `Owner`는 reverse namespace를 소유하는 target model이고 `Target`은 source relation model입니다.

`ir.Normalize`의 `*ir.ValidationError`로 거부합니다. Product package는 `conformance/relationbinding`을
import/copy하지 않고 독립 구현합니다.

## Migration fail-closed 경계

- `definition.DefinitionFormatVersion=1`, `LoaderABIVersion=1`, `OperationCodecVersion=1`,
  `SchemaIRVersion=2`와 `migrations.StateFormatVersion=1`은 변경하지 않습니다.
- Existing `CreateModel`/`AddField` operation codec와 loaded definition은 relation-bearing vNext payload를
  지원하지 않습니다.
- `migrations.NewProjectState`와 state validation은 normalized format 3 schema를 실행 I/O 전에 거부합니다.
  `CreateModel`/`AddField`의 v2 normalization wrapper도 relation field를 거부합니다.
- `NewStateReconstructor`는 built-in definition을 clone하는 constructor 단계에서 every `CreateModel` model field와
  `AddField.Field`를 preflight합니다. Cloned field가 `Kind == ir.FieldForeignKey`이거나 `Relation != nil`이면
  relation-v2 incompatibility cause를 가진 exact structured `*migrations.Error` (`CategoryState`,
  `CodeInvalidState`, `DirectionForward`, migration identity, operation index/kind)로 fail-closed하며 definition
  snapshot이나 reconstructor를 publish하지 않습니다. 이 진단은 unsupported operation-type cause를 재사용하지
  않습니다. `Executor.Migrate`는 이 constructor를 backend capability check, revision-fenced session open과
  recorder read보다 먼저 호출하므로 lifecycle에서도 backend와 recorder I/O는 exact 0입니다.
- Definition compatibility tuple의 `schema_ir=3`은 existing `schema_ir_incompatible` code를 유지합니다.
  Tuple 2 문서에 relation field shape를 숨기면 exact existing `definition.CodeInvalidIR` /
  `invalid_definition_ir`와 semantic field path로 실패하고 relation을 부분 decode하지 않습니다.
- Current v2 migration fixture/bytes/digest/planner/lifecycle tests와 external literal-version AST gates를
  그대로 통과해야 합니다.

이는 relation migration upgrade 경로가 구현됐다는 뜻이 아니라 accidental acceptance를 막는 음성 계약입니다.
Relation migration contract/codec/SQLite FK DDL은 GDJ-0024 뒤 별도 packet이 소유합니다.

## Partial product comparison과 false-green gate

Reference manifest/oracle은 12 ordered contract를 계속 모두 보유합니다. Product relation execution도 12개

  payload-free `not_implemented`를 만듭니다. Unregistered+`passing|deviation` 또는 red/draft/unknown status는
  actual publication 전 error입니다.
- Product comparison은 manifest `passing`/`deviation` contract에 `observed`, `oracle_locked` contract에
  ordered `not_implemented`/zero payload만 허용합니다.
- `red`/`draft`, unknown status, duplicate/missing/out-of-order observation은 product command exit 2이고
  성공 문구/actual output을 publish하지 않습니다.
- Mixed manifest invocation은 exact required-observed allowlist를 명시해야 하고, 그 list는 manifest의
  `passing`/`deviation` ID set과 정확히 같아야 합니다. GDJ-0024 relation set의 list는 REL-001 하나입니다.
- Unknown/unregistered scenario를 `passing`으로 바꾸면 exit 2/no actual output이어야 합니다.
- 한-contract filtered oracle/manifest를 만들어 비교하지 않습니다. REL-001 actual과 나머지 11
  not-implemented가 original 12-contract profile/order 안에 있어야 합니다.
- Existing eleven product manifests는 all-observed exact behavior와 5 reviewed deviation policy를 유지합니다.
- `godjcheck` main은 locked expected self-validation에 기존 strict `Compare`를 유지합니다. Mixed relation actual은
  `CompareProduct`와 registry-derived required IDs를 먼저 통과해야만 `-actual-output`을 씁니다. Invalid required
  IDs/status/missing/duplicate/order는 파일을 publish하지 않습니다. Existing all-observed manifests는 strict
  comparison behavior를 유지합니다.
- Validated mixed relation success stdout은 exact

- Relation oracle/static fixture/SHA는 byte-for-byte 불변이고 manifest의 reviewed status-only change 외
  title/scenario/phase/provenance/comparison은 바꾸지 않습니다.
- Django runner/scenario/oracle는 불변입니다. Existing Python status assertion만 exact
  `["passing"] + ["oracle_locked"] * 11`로 동기화하며 Python test count/digest는 바꾸지 않습니다.
